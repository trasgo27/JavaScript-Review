08 - HTTPClient

Nivel: Avanzado

En este módulo aprenderás a consumir APIs REST con HttpClient en Angular 17+. Cubriremos desde la configuración básica hasta interceptores funcionales, manejo de errores, lógica de reintento y la creación de un servicio CRUD completo.

Usaremos JSONPlaceholder como API de ejemplo para todos los ejercicios.

Conceptos clave

  • provideHttpClient() y withFetch()
  • HttpClient — inyección del servicio
  • Métodos: get(), post(), put(), delete()
  • pipe(), catchError(), retry()
  • HttpInterceptorFn — interceptores funcionales
  • HttpErrorResponse — respuesta de error tipada
  • HttpHeaders — cabeceras personalizadas
  • provideHttpClientTesting() — testing de peticiones HTTP
  • Typed responses con interfaces
01Configurar HttpClient con provideHttpClient ⭐
Objetivo
Configurar correctamente HttpClient en una aplicación Angular 17+ usando proveedores funcionales.
Enunciado
Crea una nueva aplicación Angular y configura HttpClient en el archivo app.config.ts. Asegúrate de que el servicio esté disponible para inyección en cualquier componente o servicio.
Requisitos
  • Usa provideHttpClient() dentro de bootstrapApplication()
  • Añade withFetch() para usar la API Fetch en vez de XMLHttpRequest
  • Inyecta HttpClient en un componente y realiza un GET a https://jsonplaceholder.typicode.com/posts
  • Muestra la cantidad de resultados en la consola
En Angular 17+ la configuración se hace en app.config.ts con importProvidersFrom o directamente con provideHttpClient(withFetch()) como argumento de bootstrapApplication.
02Petición GET: obtener una lista de elementos ⭐
Objetivo
Realizar una petición GET y mostrar los resultados en una lista.
Enunciado
Crea un servicio PostService que inyecte HttpClient. Crea un método getPosts() que devuelva un Observable<any[]> con los posts de JSONPlaceholder. En el componente PostListComponent, suscríbete al observable y renderiza una lista con el título de cada post.
Requisitos
  • Crear servicio con ng generate service services/post
  • El método getPosts() debe retornar this.http.get<any[]>('https://jsonplaceholder.typicode.com/posts')
  • En el componente usar subscribe() para obtener los datos
  • Renderizar cada post con su id y title
  • Implementar una variable loading para mostrar un indicador mientras se carga
Recuerda que HttpClient.get() retorna un Observable. Puedes usar finalize() en el pipe para desactivar el estado de carga cuando la petición termine (exitosa o con error).
03GET con parámetros de consulta ⭐⭐
Objetivo
Enviar parámetros de consulta (query params) en una petición GET.
Enunciado
Modifica el servicio PostService para que el método getPosts() acepte parámetros opcionales: userId (número) y _limit (número). Crea un componente con dos campos de entrada (input numérico y selector) que filtre los posts al cambiar los valores. Usa HttpParams para construir los parámetros.
Requisitos
  • Importar HttpParams desde @angular/common/http
  • El método debe construir HttpParams solo con los valores definidos (no incluir params vacíos)
  • Endpoint: https://jsonplaceholder.typicode.com/posts
  • Usar signal() o BehaviorSubject para reaccionar a cambios en los filtros
  • Debounce de 300ms en el input para evitar peticiones excesivas usando debounceTime
Construye los HttpParams de forma condicional: let params = new HttpParams(); if (userId) params = params.set('userId', userId);. Usa debounceTime(300) y distinctUntilChanged() en el pipe del Observable del input.
04Petición POST: crear un nuevo recurso ⭐⭐
Objetivo
Crear un nuevo recurso enviando datos en el cuerpo de una petición POST.
Enunciado
Crea un componente PostFormComponent con un formulario reactivo que tenga campos: title (texto) y body (textarea). Al enviar el formulario, haz una petición POST a JSONPlaceholder para crear un post. Muestra la respuesta del servidor (el ID asignado) tras el envío exitoso.
Requisitos
  • Usar FormBuilder y FormGroup para el formulario
  • Método createPost(post: any) en el servicio que use this.http.post()
  • Endpoint: https://jsonplaceholder.typicode.com/posts
  • Configurar cabeceras Content-Type: application/json con HttpHeaders
  • Mostrar un mensaje de éxito con el id del post creado
  • Deshabilitar el botón de envío mientras se procesa la petición
JSONPlaceholder simula la creación y retorna un objeto con el id. Puedes pasar las cabeceras como segundo argumento: this.http.post(url, body, { headers }). Usa finalize() para rehabilitar el botón.
05Petición PUT: actualizar un recurso ⭐⭐
Objetivo
Actualizar un recurso existente enviando datos completos en una petición PUT.
Enunciado
Crea un componente PostEditComponent que reciba un id por ruta. Al cargar, obtén el post con GET y rellena un formulario de edición. Al guardar, envía una petición PUT con los datos actualizados. Muestra el resultado actualizado.
Requisitos
  • Configurar ruta parametrizada: posts/:id/edit
  • Usar ActivatedRoute para obtener el id
  • Método updatePost(id: number, post: any) usando this.http.put()
  • Endpoint: https://jsonplaceholder.typicode.com/posts/{id}
  • Precargar el formulario con los datos actuales del post
  • Mostrar confirmación de actualización con los datos devueltos
Para precargar el formulario, subscribe al GET del post y usa patchValue() sobre el FormGroup. La diferencia con setValue() es que patchValue() no requiere todos los campos.
06Petición DELETE: eliminar un recurso ⭐⭐
Objetivo
Eliminar un recurso con una petición DELETE y actualizar la vista.
Enunciado
Añade a la lista de posts un botón de eliminar en cada elemento. Al hacer clic, muestra una confirmación y luego envía una petición DELETE. Si es exitosa, elimina el post de la lista local sin volver a cargar todos los datos.
Requisitos
  • Método deletePost(id: number) en el servicio usando this.http.delete()
  • Endpoint: https://jsonplaceholder.typicode.com/posts/{id}
  • Confirmación antes de eliminar con confirm() o un modal
  • Actualizar el array local de posts tras la eliminación (sin recargar)
  • Mostrar feedback visual: post eliminado con animación o cambio de estilo antes de quitarlo
  • Manejar el caso de error mostrando un mensaje al usuario
Para la eliminación local, filtra el array: this.posts = this.posts.filter(p => p.id !== id). Puedes usar switchMap para encadenar la confirmación con la petición HTTP.
07Manejo de errores con catchError ⭐⭐⭐
Objetivo
Implementar un manejo robusto de errores HTTP usando catchError y HttpErrorResponse.
Enunciado
Crea un servicio de error HTTP centralizado que maneje los diferentes tipos de errores (404, 500, timeout, errores de red). Usa catchError en el pipe de cada petición. Crea un interceptor funcional que muestre errores globales y un componente de notificaciones que muestre los mensajes de error al usuario.
Requisitos
  • Crear función handleError(error: HttpErrorResponse) que retorne un Observable
  • Distinguir entre errores del servidor (error.status), de red (error.status === 0) y de configuración
  • Usar catchError(this.handleError) en el pipe de cada petición en el servicio
  • Crear un ErrorInterceptor funcional que use inject()
  • Crear un servicio NotificationService con un BehaviorSubject para propagar mensajes de error
  • Mostrar errores en un componente toast/snackbar
Un interceptor funcional en Angular 17+ se define como: export const errorInterceptor: HttpInterceptorFn = (req, next) => { ... }. Puedes usar tap() en el pipe del observable del interceptor para capturar errores del lado del servidor.
08Lógica de reintento con retry() ⭐⭐⭐
Objetivo
Implementar lógica de reintento automático para peticiones que fallen transitoriamente.
Enunciado
Crea un servicio que simule una API inestable. Configura la lógica de reintento con retry() para que reintente automáticamente hasta 3 veces antes de propagar el error. Implementa un delay exponencial entre reintentos y muestra en consola cuántos reintentos se realizaron.
Requisitos
  • Usar retry({ count: 3, delay: 1000, resetOnSuccess: true })
  • Configurar delay exponencial: 1s, 2s, 4s usando la función delay personalizada
  • Crear un componente que muestre el estado: "Cargando...", "Reintentando (intento X)...", "Error tras 3 intentos", "Éxito"
  • Usar tap() para loggear cada reintento en consola
  • Simular fallo aleatorio: crear un mock interceptor que falle el 50% de las peticiones
retry() en RxJS 7+ acepta un objeto de configuración. El parámetro delay puede ser una función que recibe el retryCount y retorna un Observable: delay: (retryCount) => timer(retryCount * 1000). Usa finalize() para detectar cuándo se completó el reintento.
09Interceptor HTTP: añadir token de autenticación ⭐⭐⭐⭐
Objetivo
Crear un interceptor funcional que añada automáticamente un token de autenticación a todas las peticiones HTTP.
Enunciado
Crea un interceptor funcional que lea un token de un servicio de autenticación y lo añada como cabecera Authorization a cada petición. Configúralo con provideHttpClient(withInterceptors([...])). Crea un servicio de auth simulado y un componente de login que guarde el token.
Requisitos
  • Crear servicio AuthService con BehaviorSubject<string | null> para el token
  • Crear interceptor funcional: export const authInterceptor: HttpInterceptorFn = (req, next) => { ... }
  • Usar inject(AuthService) dentro del interceptor para obtener el token
  • Clonar la request con req.clone({ setHeaders: { Authorization: 'Bearer ' + token } })
  • No añadir la cabecera si la URL es pública (ej: /auth/login)
  • Registrar el interceptor: provideHttpClient(withInterceptors([authInterceptor]))
  • Crear componente login simple que simule el login y almacene el token
Los interceptores funcionales usan inject() en vez del constructor. Usa req.clone() para modificar la petición sin mutarla. Puedes verificar la URL con req.url para decidir si añadir la cabecera o no.
10Interceptor HTTP: logging de peticiones ⭐⭐⭐⭐
Objetivo
Crear un interceptor que registre información detallada de cada petición HTTP: método, URL, duración, código de respuesta y tamaño.
Enunciado
Crea un interceptor funcional de logging que mida el tiempo de cada petición, registre los detalles en consola con formato estructurado y almacene un historial de peticiones accesible desde un componente administrativo.
Requisitos
  • Crear servicio HttpLogService con array de logs tipados: { method, url, startTime, endTime, duration, status, body }
  • Interceptor funcional que capture el timestamp antes y después de cada petición
  • Usar tap() para medir el tiempo de respuesta
  • Formato de log: [HTTP] GET /posts 200 (142ms)
  • Crear componente HttpLogComponent que muestre el historial en una tabla ordenada
  • Limitar el historial a las últimas 50 peticiones
  • Registrar errores también: [HTTP] GET /posts/999 404 (38ms)
Usa Date.now() para medir la duración. En el interceptor puedes usar finalize() en el observable retornado por next(req) para registrar al finalizar. Para mostrar logs en tiempo real, usa un BehaviorSubject en el servicio y suscríbete con async pipe.
11Respuestas tipadas con interfaces ⭐⭐⭐⭐
Objetivo
Definir interfaces TypeScript para tipar correctamente las respuestas y peticiones HTTP.
Enunciado
Refactoriza el servicio de posts para que todas las respuestas estén tipadas. Crea interfaces para Post, User, Comment y ApiResponse. Implementa una función genérica que transforme la respuesta del servidor a un modelo de dominio antes de exponerlo al componente.
Requisitos
  • Crear models/post.model.ts con interface Post: id, userId, title, body
  • Crear interface User: id, name, email, phone, company
  • Crear interface Comment: id, postId, name, email, body
  • Usar genéricos: this.http.get<Post[]>(url) en el servicio
  • Crear función mapPost(raw: any): Post para transformar datos si la API devuelve campos extras
  • Usar map() en el pipe para transformar cada elemento de la respuesta
  • Crear un componente PostDetailComponent que muestre un post con su autor y comentarios, todo tipado
Para el detail con relaciones, puedes usar switchMap para encadenar peticiones: primero obtener el post, luego el usuario con post.userId, y finalmente los comentarios con forkJoin. Definir interfaces te da autocompletado en el template con @if (post).
12Servicio CRUD completo: Gestor de contactos ⭐⭐⭐⭐⭐
Objetivo
Construir un servicio CRUD completo con manejo de errores, interceptores, tipado y una interfaz de usuario funcional.
Enunciado
Crea una aplicación completa de gestión de contactos usando JSONPlaceholder. Implementa un servicio ContactService con todas las operaciones CRUD, interceptores de autenticación y logging, manejo centralizado de errores, y una interfaz de usuario con lista, formulario de creación/edición y eliminación.
Requisitos
  • Interface Contact: id, name, email, phone, website (mapear desde User de JSONPlaceholder)
  • ContactService con métodos: getAll(), getById(id), create(contact), update(id, contact), delete(id), search(query)
  • Cada método tipado con Observable<Contact> o Observable<Contact[]>
  • Interceptor de autenticación funcional que añada token a todas las peticiones
  • Interceptor de logging que registre cada operación CRUD
  • catchError centralizado que distinga entre errores CRUD y propague mensajes claros
  • Componente lista con búsqueda en tiempo real (debounceTime + switchMap)
  • Componente formulario reutilizable para crear y editar (detectar modo con parámetro de ruta)
  • Confirmación visual tras cada operación (creación, edición, eliminación)
  • Estado de carga en cada operación con spinner/indicador
  • Routing configurado: /contacts, /contacts/new, /contacts/:id/edit
Para la búsqueda en tiempo real, usa un Subject como emisor de términos de búsqueda. Conecta el input al subject con subject.next(value), y en el servicio usa subject.pipe(debounceTime(300), distinctUntilChanged(), switchMap(term => this.http.get(...))). Para detectar si el formulario está en modo edición, verifica si el parámetro :id existe en la ruta con ActivatedRoute.paramMap.
