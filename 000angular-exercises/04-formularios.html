04 - Formularios

Los formularios son el principal punto de interacción entre el usuario y la aplicación. Angular ofrece dos enfoques completamente diferentes para gestionarlos: los Template-driven forms, más sencillos y basados en directivas del template, y los Reactive forms, más poderosos y basados en modelos de datos en el componente.

En este módulo intermedio dominarás ambos enfoques. Empezarás con formularios simples guiados por plantilla, avanzarás a la gestión reactiva de formularios complejos con validación, y culminarás integrando todos los conceptos en un formulario de registro completo. Cada ejercicio construye sobre el anterior.

Todos los ejemplos usan la sintaxis moderna de Angular 17+ con componentes standalone.

Conceptos clave

  • ngModel — Directiva de two-way binding para formularios template-driven
  • FormsModule — Módulo necesario para formularios template-driven
  • ReactiveFormsModule — Módulo necesario para formularios reactivos
  • FormGroup — Agrupación de controles que representa un formulario completo o un sub-formulario
  • FormControl — Control individual que gestiona un valor, estado de validación y observadores
  • FormArray — Colección dinámica de controles que permite agregar y eliminar elementos en tiempo de ejecución
  • Validators — Validadores integrados: required, email, minLength, maxLength, pattern, min, max
  • Validadores personalizados — Funciones que reciben AbstractControl y retornan ValidationErrors | null
  • FormBuilder — Servicio auxiliar que simplifica la creación de formularios reactivos con menos código
  • valueChanges — Observable que emite cada vez que el valor del control o grupo cambia
  • statusChanges — Observable que emite cuando el estado de validación del control cambia
  • Estados touched / dirty / valid — Propiedades que controlan cuándo y cómo mostrar errores de validación
01Formulario básico con ngModel ⭐
Objetivo
Familiarizarte con el enfoque template-driven de Angular usando ngModel para enlace bidireccional de datos entre el template y el componente.
Enunciado
Crea un componente de formulario que permita al usuario ingresar su nombre completo y correo electrónico. Cada campo debe estar enlazado bidireccionalmente con una propiedad del componente usando [(ngModel)]. Debajo del formulario, incluye una sección de "Vista previa del perfil" que muestre en tiempo real los valores ingresados por el usuario, actualizándose carácter a carácter mientras escribe.
Requisitos
  • Crear un componente standalone PerfilBasicoComponent con standalone: true
  • Importar FormsModule en el array imports del decorador @Component
  • Definir un objeto perfil en la clase con propiedades nombre (string) e email (string)
  • Inicializar el objeto con valores vacíos: { nombre: '', email: '' }
  • Crear dos campos <input> enlazados con [(ngModel)]="perfil.nombre" y [(ngModel)]="perfil.email"
  • Los campos deben tener atributos placeholder descriptivos
  • Agregar etiquetas <label> asociadas a cada campo con for e id
  • Mostrar la vista previa del perfil debajo del formulario usando interpolación {{ perfil.nombre }} y {{ perfil.email }}
  • La vista previa debe tener un título "Vista previa del perfil" y mostrar los valores en un formato visual agradable
  • Si el nombre está vacío, mostrar "Sin nombre" en la vista previa como texto placeholder
  • Si el email está vacío, mostrar "Sin email" en la vista previa como texto placeholder
En componentes standalone, FormsModule se importa directamente en el array imports del decorador @Component, igual que se importan componentes. No necesitas un módulo NgModule. Usa un <form> como contenedor aunque no tengas validación aún; es una buena práctica que prepara el terreno para los siguientes ejercicios.
02Validaciones con atributos de plantilla ⭐⭐
Objetivo
Aplicar validaciones integradas en un formulario template-driven utilizando atributos HTML y directivas Angular de validación.
Enunciado
Extendiendo el formulario del ejercicio anterior, agrega validación robusta a cada campo. Cada campo debe tener reglas de validación específicas y el formulario debe reflejar visualmente si cada campo es válido o inválido. Agrega un tercer campo de teléfono con validación por patrón regex.
Requisitos
  • Campo nombre: usar required y minlength="3"
  • Campo email: usar required y email (validación nativa del navegador + Angular)
  • Campo teléfono: usar required y pattern="^[+]?[0-9\s\-]{7,15}$"
  • Crear referencia de template para cada campo: #nombreField="ngModel", #emailField="ngModel", #telField="ngModel"
  • Mostrar junto a cada campo un indicador visual del estado: "Válido" en verde o "Inválido" en rojo, usando interpolación con la propiedad .valid de cada referencia de template
  • Aplicar una clase CSS condicional al campo: [ngClass]="{'campo-invalido': emailField.invalid}"
  • Mostrar el objeto de errores completo de cada campo usando {{ nombreField.errors | json }} para que se pueda inspeccionar la estructura de errores
  • El formulario solo debe mostrar como válido cuando TODOS los campos sean válidos simultáneamente
Las referencias de template con ="ngModel" te dan acceso a propiedades como valid, invalid, errors (un objeto con los errores activos), touched, untouched, dirty y pristine. El objeto errors contiene claves como { required: true } o { minlength: { requiredLength: 3, actualLength: 1 } }.
03Mostrar errores de validación ⭐⭐
Objetivo
Implementar mensajes de error contextuales que se muestren solo cuando el usuario ha interactuado con un campo, evitando mostrar errores prematuramente.
Enunciado
Modifica el formulario del ejercicio anterior para que muestre mensajes de error específicos debajo de cada campo. Los errores solo deben aparecer cuando el campo ha sido tocado por el usuario (blur o interacción) y es inválido. Cada tipo de error debe tener un mensaje diferente y descriptivo en español.
Requisitos
  • Los errores solo se muestran cuando touched es true Y el campo es invalid
  • Campo nombre: mensaje "El nombre es requerido" para error required; "El nombre debe tener al menos 3 caracteres (faltan X)" para error minlength
  • Campo email: mensaje "El correo electrónico es requerido" para required; "Ingrese un correo electrónico válido" para error email
  • Campo teléfono: mensaje "El teléfono es requerido" para required; "Formato de teléfono inválido. Ejemplo: +54 11 1234-5678" para error pattern
  • Crear una clase CSS .error-msg con color rojo (#ff6b6b), tamaño de fuente 0.85rem y margen superior 4px
  • Usar *ngIf con la condición completa: *ngIf="nombreField.invalid && nombreField.touched"
  • Agregar un segundo bloque de *ngIf que muestre mensajes específicos según la clave del error: nombreField.errors?.['required'], nombreField.errors?.['minlength']
  • Para el error de minlength, mostrar cuántos caracteres faltan usando nombreField.errors?.['minlength'].requiredLength - nombreField.errors?.['minlength'].actualLength
  • Los indicadores de estado (Válido/Inválido) solo deben mostrarse cuando el campo ha sido tocado
La sintaxis nombreField.errors?.['minlength'] usa optional chaining porque errors puede ser null cuando el campo es válido. El objeto de error de minlength contiene requiredLength (el mínimo) y actualLength (lo que el usuario ha escrito). Puedes calcular los caracteres faltantes restando ambos valores.
04Envío y reset de formulario ⭐⭐⭐
Objetivo
Dominar el ciclo de vida de un formulario template-driven: envío, procesamiento, retroalimentación al usuario y reinicio limpio.
Enunciado
Crea un formulario de contacto con campos: asunto (input text), mensaje (textarea) y categoría (select con opciones: Soporte técnico, Sugerencia, Reclamo, Otro). El formulario debe validar antes de enviar, mostrar un mensaje de éxito temporal, resetear todos los campos y deshabilitar el botón de envío mientras el formulario no sea válido. Después de enviar, el mensaje de éxito debe desaparecer automáticamente.
Requisitos
  • Usar la directiva (ngSubmit) en el elemento <form> para manejar el envío
  • Crear referencia de template del formulario: #contactForm="ngForm"
  • Vincular el atributo [disabled] del botón de envío con contactForm.invalid
  • Validar que todos los campos sean requeridos: asunto, mensaje y categoría
  • El campo mensaje (<textarea>) debe tener minlength="10"
  • Crear un método onSubmit() en el componente que:
  • Reciba el formulario como referencia y acceda a su valor
  • Establezca una bandera mensajeEnviado = true
  • Llame a contactForm.resetForm() para limpiar todos los campos y estados
  • Use setTimeout de 3 segundos para ocultar el mensaje de éxito
  • Mostrar un banner de éxito con *ngIf="mensajeEnviado" que diga "¡Mensaje enviado exitosamente!"
  • Mostrar los errores de validación por campo usando la misma lógica del ejercicio anterior
  • Incluir el campo select con [(ngModel)]="categoria" y opciones predefinidas
  • Agregar una referencia de template al select: #catField="ngModel"
El método resetForm() de la referencia NgForm restablece todos los valores a vacío y resetea los estados de validación (touched, dirty, etc.). Puedes pasarle un objeto para establecer valores por defecto después del reset, por ejemplo: contactForm.resetForm({ categoria: 'soporte' }). Para acceder al valor del formulario dentro de onSubmit, usa la referencia contactForm.value.
05FormGroup y FormControl con Reactive Forms ⭐⭐⭐
Objetivo
Configurar un formulario reactivo desde cero usando FormGroup y FormControl, entendiendo la diferencia fundamental con el enfoque template-driven.
Enunciado
Crea un formulario reactivo de edición de perfil con los campos: nombre de usuario, biografía (textarea) y sitio web. El formulario debe inicializarse con valores por defecto, cada campo debe reflejar su estado de validación visualmente, y el valor completo del formulario debe mostrarse en tiempo real en una sección de inspección.
Requisitos
  • Importar ReactiveFormsModule en los imports del componente standalone
  • NO importar FormsModule (los formularios reactivos no lo necesitan)
  • Crear un FormGroup en la propiedad perfilForm del componente usando new FormGroup({...})
  • Crear tres FormControl: usuario (valor: 'mi_usuario'), biografia (valor: ''), sitioWeb (valor: '')
  • Vincular el formulario al template con [formGroup]="perfilForm" en el elemento <form>
  • Vincular cada campo con formControlName="usuario", formControlName="biografia", formControlName="sitioWeb"
  • Acceder al estado de cada control usando perfilForm.get('usuario') o perfilForm.controls['usuario']
  • Mostrar el estado del formulario completo: perfilForm.valid, perfilForm.dirty, perfilForm.pristine
  • Mostrar el valor del formulario en tiempo real con {{ perfilForm.value | json }} dentro de un bloque <pre>
  • Mostrar un indicador de "Cambios sin guardar" cuando perfilForm.dirty && perfilForm.valid
  • Agregar un botón "Guardar" deshabilitado cuando el formulario no es válido
A diferencia de los formularios template-driven donde el modelo de datos vive en el componente y se enlaza al template, en los reactive forms el modelo de datos vive en el FormGroup y se expone al template. El FormGroup es la fuente de verdad. Puedes acceder a cualquier control con perfilForm.get('nombreCampo') que retorna un AbstractControl.
06Validadores integrados en Reactive Forms ⭐⭐⭐
Objetivo
Dominar los validadores integrados de Validators en formularios reactivos y simplificar la creación del formulario con FormBuilder.
Enunciado
Crea un formulario de registro con los campos: nombre completo, correo electrónico y contraseña. Utiliza FormBuilder para declarar el formulario de forma concisa, aplica validadores integrados robustos a cada campo, y muestra los errores específicos debajo de cada uno. Los errores solo deben mostrarse cuando el campo haya sido tocado.
Requisitos
  • Inyectar FormBuilder en el constructor del componente
  • Crear el formulario con this.fb.group({...}) en lugar de new FormGroup({...})
  • Campo nombre: ['', [Validators.required, Validators.minLength(5)]]
  • Campo email: ['', [Validators.required, Validators.email]]
  • Campo contraseña: ['', [Validators.required, Validators.minLength(8)]]
  • Crear un array camposConfig con los metadatos de cada campo: nombre, etiqueta, tipo de input, y la referencia al control
  • Iterar los campos con *ngFor="let campo of camposConfig" para generar el formulario dinámicamente
  • Para cada campo, mostrar errores específicos: required → "Este campo es requerido"; minlength → "Mínimo X caracteres"; email → "Email inválido"
  • Usar la condición control.touched && control.invalid para mostrar/ocultar errores
  • Crear un botón "Registrar" deshabilitado cuando el formulario no es válido
  • Mostrar un resumen del estado del formulario: cuántos campos son válidos de un total
FormBuilder es un servicio inyectable que simplifica la creación de formularios. En lugar de escribir new FormGroup({ nombre: new FormControl('', Validators.required) }), puedes escribir this.fb.group({ nombre: ['', Validators.required] }). El primer elemento del array es el valor inicial, el segundo es el validador o array de validadores.
07Validador personalizado de fortaleza de contraseña ⭐⭐⭐⭐
Objetivo
Crear un validador personalizado que evalúe la fortaleza de una contraseña con múltiples criterios y proporcionar retroalimentación visual en tiempo real.
Enunciado
Implementa un validador personalizado passwordStrength que verifique que la contraseña cumpla con 4 requisitos de seguridad: al menos 8 caracteres, una letra mayúscula, un número y un carácter especial (!@#$%^&*). El campo debe mostrar indicadores visuales de qué requisitos se cumplen y cuáles no, actualizándose en tiempo real mientras el usuario escribe.
Requisitos
  • Crear una función passwordStrength(control: AbstractControl): ValidationErrors | null como método o función separada
  • La función debe retornar null si TODAS las condiciones se cumplen (contraseña válida)
  • Si alguna condición no se cumple, retornar un objeto con el estado de cada condición:
  • { minLength: true/false, hasUpperCase: true/false, hasNumber: true/false, hasSpecialChar: true/false }
  • Usar expresiones regulares para verificar cada condición: [A-Z], [0-9], [!@#$%^&*]
  • Crear una lista visual de requisitos en la vista con ícono ✓ (verde) o ✗ (rojo) para cada condición
  • Acceder a los errores del control en la vista: passwordControl.errors?.['hasUpperCase']
  • Cada indicador debe actualizarse en tiempo real mientras el usuario escribe
  • El campo de contraseña debe tener el validador integrado: [Validators.required, this.passwordStrength]
  • Mostrar un indicador general de fortaleza: "Débil" (0-1 requisitos), "Media" (2-3 requisitos), "Fuerte" (4 requisitos)
  • Usar colores para la fortaleza: rojo para débil, amarillo para media, verde para fuerte
Un validador personalizado es una función que recibe un AbstractControl y retorna null si es válido o un objeto ValidationErrors con cualquier estructura que tu vista necesite. El objeto de errores se actualiza automáticamente cada vez que el valor del control cambia, por lo que tu vista reaccionará sin código adicional. Usa control.value para obtener el valor actual y expresiones regulares con .test() para verificar patrones.
08FormGroup anidado (dirección dentro de perfil) ⭐⭐⭐⭐
Objetivo
Estructurar formularios complejos con jerarquía usando FormGroup anidados para representar objetos con estructura jerárquica.
Enunciado
Crea un formulario de perfil completo que contenga un FormGroup anidado para la dirección. El formulario principal incluye nombre y email, mientras que el sub-formulario de dirección incluye calle, ciudad, código postal y país. Ambos niveles deben tener validaciones independientes, y el valor del formulario debe reflejar la estructura jerárquica en el objeto resultante.
Requisitos
  • Crear un FormGroup principal llamado perfilForm usando FormBuilder
  • Dentro de perfilForm, crear un FormGroup anidado llamado direccion
  • Campos del perfil principal: nombre (required, minLength 3) y email (required, email)
  • Campos de dirección: calle (required), ciudad (required, minLength 3), codigoPostal (required, pattern: /^[0-9]{5}$/), pais (required)
  • En el template, usar formGroupName="direccion" en un contenedor <fieldset> para agrupar visualmente los campos de dirección
  • Los formControlName de dirección deben estar DENTRO del formGroupName
  • El valor resultante del formulario debe tener la estructura: { nombre: '...', email: '...', direccion: { calle: '...', ciudad: '...', codigoPostal: '...', pais: '...' } }
  • Mostrar el valor completo del formulario formateado con {{ perfilForm.value | json }} en un bloque <pre>
  • Deshabilitar el botón guardar si el formulario completo no es válido
  • Mostrar errores específicos para cada campo, incluyendo los anidados, solo cuando han sido tocados
  • Incluir un campo <select> para el país con opciones: España, México, Argentina, Colombia, Chile
  • Campo código postal debe aceptar solo 5 dígitos numéricos (validación con pattern y maxlength="5")
Los FormGroup anidados se declaran como valores dentro de otro FormGroup. En el template, formGroupName establece el contexto de bindings para los formControlName hijos. Para acceder a un control anidado desde el componente, usa this.perfilForm.get('direccion.codigoPostal'). La estructura del objeto resultado refleja automáticamente la jerarquía del formulario.
09FormArray: lista dinámica de habilidades ⭐⭐⭐⭐⭐
Objetivo
Gestionar una lista dinámica de campos usando FormArray para agregar y eliminar elementos en tiempo de ejecución.
Enunciado
Crea un formulario de perfil de desarrollador que incluya un FormArray de habilidades. El usuario debe poder agregar nuevas habilidades con un botón "Agregar habilidad" y eliminar las existentes con un botón "X" en cada fila. Cada habilidad consta de un campo de texto (nombre de la tecnología) y un select de nivel de experiencia.
Requisitos
  • Crear un FormGroup con campo nombreDesarrollador (required) y un FormArray llamado habilidades
  • Crear un getter get habilidades(): FormArray para acceder al FormArray desde el template y la clase
  • Cada elemento del FormArray es un FormGroup con: tecnologia (required, minLength 2) y nivel (required, valor por defecto: 'basico')
  • Implementar método agregarHabilidad() que haga push() un nuevo FormGroup al FormArray
  • Implementar método eliminarHabilidad(index: number) que haga removeAt(index)
  • Iterar las habilidades con *ngFor="let habilidad of habilidades.controls; let i = index"
  • El select de nivel debe tener opciones: Básico, Intermedio, Avanzado, Experto
  • Mostrar el contador de habilidades: "X habilidades agregadas"
  • El botón "Agregar habilidad" NO debe aparecer si ya hay 10 habilidades (máximo)
  • Mostrar un mensaje "No hay habilidades. Agrega al menos una." cuando el array esté vacío
  • Cada fila de habilidad debe tener un botón "Eliminar" que remueva solo esa fila
  • El botón "Guardar perfil" debe estar deshabilitado si el formulario no es válido O si no hay al menos 1 habilidad
  • Mostrar el valor del formulario completo incluyendo el array de habilidades con | json
Para acceder al FormArray desde el template, crea un getter en la clase: get habilidades() { return this.perfilForm.get('habilidades') as FormArray; }. No olvides importar FormArray desde @angular/forms. El método push() agrega un nuevo control al final del array, y removeAt(index) elimina el control en la posición indicada. Para verificar que hay al menos una habilidad, usa habilidades.length > 0.
10FormArray con filas dinámicas en tabla (items de pedido) ⭐⭐⭐⭐⭐
Objetivo
Construir una tabla editable con filas dinámicas usando FormArray y realizar cálculos reactivos sobre los datos del formulario.
Enunciado
Crea un formulario de pedido que muestre una tabla editable. Cada fila de la tabla contiene: nombre del producto, cantidad y precio unitario. El formulario debe calcular automáticamente el subtotal de cada fila y el total general del pedido. El usuario debe poder agregar y eliminar filas de la tabla. El total debe actualizarse en tiempo real.
Requisitos
  • Crear un FormGroup con campo cliente (required) y FormArray llamado items
  • Cada item del FormArray es un FormGroup con: producto (required), cantidad (required, min: 1), precioUnitario (required, min: 0.01)
  • Crear getter get items(): FormArray
  • Calcular subtotal de cada fila: fila.get('cantidad')!.value * fila.get('precioUnitario')!.value
  • Crear un getter get totalPedido(): number que recorra todos los items y sume sus subtotales
  • Crear un getter get totalItems(): number que sume todas las cantidades
  • Mostrar la tabla con <table> HTML, <thead> con encabezados y <tbody> con *ngFor
  • Columnas de la tabla: # (índice), Producto, Cantidad, Precio Unitario, Subtotal, Acciones
  • Botón "Agregar item" debajo de la tabla que añada una fila vacía al FormArray
  • Botón "Eliminar" en la columna de acciones de cada fila que remueva ese item específico
  • Fila de totales al final de la tabla mostrando: total de items, total de unidades y total en dinero
  • Formato de moneda para precios: usar | currency:'USD':'symbol':'1.2-2'
  • El botón "Agregar item" NO debe aparecer si ya hay 8 items (máximo)
  • Mostrar un mensaje de tabla vacía cuando no haya items
Para calcular el total, recorre this.items.controls y para cada FormGroup obtén los valores con control.value o accede a cada control individual con control.get('cantidad')!.value. El pipe currency formatea automáticamente los números como moneda. Usa *ngIf="items.length === 0" para mostrar el mensaje de tabla vacía.
11Reactive form con valueChanges ⭐⭐⭐⭐⭐
Objetivo
Reaccionar programáticamente a cambios de valores y estado en un formulario reactivo usando valueChanges, statusChanges y operadores de RxJS.
Enunciado
Crea un componente de búsqueda y filtrado que contenga un formulario reactivo con campos de búsqueda y filtros. Suscríbete a valueChanges del campo de búsqueda para simular una búsqueda en tiempo real con debounce, y a statusChanges del formulario para mostrar el estado de validación actual. Implementa la gestión adecuada de suscripciones para evitar memory leaks.
Requisitos
  • Crear un FormGroup con campos: termino (required, minLength 2), categoria (select, required), soloDisponibles (checkbox)
  • Opciones de categoría: Todos, Electrónica, Ropa, Hogar, Deportes
  • Suscribirse a termino.valueChanges en el ngOnInit del componente
  • Aplicar debounce de 300ms usando debounceTime(300) al observable del campo de búsqueda
  • Aplicar distinctUntilChanged() para evitar búsquedas duplicadas
  • Simular una búsqueda: mostrar el término buscado en un array de "resultados simulados"
  • Suscribirse a statusChanges del formulario completo para mostrar si el formulario es "Válido" o "Inválido" en tiempo real
  • Mostrar un historial de los últimos 5 términos buscados (almacenados en un array historial)
  • Mostrar un indicador de "Buscando..." que aparezca 500ms después del cambio y desaparezca después de 1 segundo (simular delay de red)
  • Implementar la limpieza de suscripciones usando DestroyRef con takeUntilDestroyed() (Angular 16+)
  • Importar debounceTime y distinctUntilChanged desde rxjs/operators
  • Mostrar un "panel de depuración" con: último valor emitido por valueChanges, estado actual del formulario, cantidad de búsquedas realizadas
valueChanges es un observable que emite cada vez que el valor de un control o grupo cambia. Puedes encadenar operadores RxJS como pipe(debounceTime(300), distinctUntilChanged()). DestroyRef se inyecta con inject(DestroyRef) en la propiedad de la clase, y takeUntilDestroyed() completa la suscripción cuando el componente se destruye. Para suscribirte a statusChanges del grupo completo, usa this.busquedaForm.statusChanges.
12Formulario completo de registro ⭐⭐⭐⭐⭐
Objetivo
Integrar TODOS los conceptos de formularios vistos en este módulo en un único formulario completo de registro con validación avanzada, estructura jerárquica, campos dinámicos y manejo de envío.
Enunciado
Construye un formulario de registro completo que combine todos los patrones aprendidos. El formulario incluye datos personales con contraseña segura, dirección postal, habilidades técnicas dinámicas y preferencias de usuario. Debe tener validación robusta en todos los niveles, validadores personalizados, validación cruzada y manejo completo del ciclo de envío.
Requisitos
  • Datos personales (FormGroup principal):
  • nombre: required, minLength(3)
  • email: required, email
  • contrasena: required, minLength(8), validador personalizado passwordStrength (mayúscula, número, especial)
  • confirmarContrasena: required — debe coincidir con contrasena (validación cruzada a nivel de grupo)
  • Dirección (FormGroup anidado direccion):
  • calle: required
  • ciudad: required, minLength(3)
  • codigoPostal: required, pattern /^[0-9]{5}$/
  • pais: required (select con 5 países)
  • Habilidades (FormArray habilidades):
  • Cada habilidad: nombre (required) + nivel (required, select: Básico/Intermedio/Avanzado/Experto)
  • Mínimo 1 habilidad, máximo 8
  • Botón agregar y botón eliminar por fila
  • Preferencias:
  • idioma: required (select: Español, English, Português)
  • aceptaTerminos: requiredTrue (checkbox obligatorio)
  • newsletter: opcional (checkbox)
  • Validación cruzada:
  • Validador passwordMatch a nivel de grupo que compare contrasena y confirmarContrasena
  • Si no coinciden, mostrar error en el campo confirmarContrasena
  • Progreso:
  • Barra de progreso que muestre el porcentaje de campos válidos del formulario
  • Calcular: (campos válidos / total de campos) * 100
  • Envío y reset:
  • Botón "Registrar" deshabilitado hasta que todo el formulario sea válido
  • Al enviar, mostrar un resumen JSON formateado de todos los datos del formulario
  • Botón "Limpiar formulario" que muestre confirmación antes de ejecutar reset()
  • Mostrar mensaje de éxito temporal de 5 segundos después del envío

Para la validación cruzada de contraseñas, usa this.fb.group({...}, { validators: this.passwordMatchValidator }) como segundo argumento de fb.group(). El validador a nivel de grupo recibe el AbstractControl del grupo completo y puede acceder a sus hijos con group.get('contrasena')?.value. Para la barra de progreso, crea un getter que recorra todos los controles del grupo principal, el FormArray y los controles del grupo anidado, contando cuántos son válidos. Recuerda que un FormArray con 0 elementos es inválido si tiene validadores, así que maneja esa caso en el cálculo del progreso.
