03 - Componentes y Comunicación

Objetivo del módulo: Dominar la comunicación entre componentes en Angular 17+ usando las APIs modernas: input(), output(), model(), content projection, ViewChild y patrones de arquitectura.

Tiempo estimado: 4-5 horas

Conceptos Clave

  • input(): declara propiedades de entrada con tipado fuerte y alias opcional
  • output(): crea flujos de eventos para notificar al componente padre
  • model(): two-way binding nativo con [(...)] entre padre e hijo
  • EventEmitter: emisor de eventos usado internamente por output()
  • ng-content: content projection para componer componentes flexible
  • @ViewChild y @ContentChild: acceso a elementos del template y contenido proyectado
  • #ref: template reference variables para acceder a instancias de componentes
  • @defer: carga diferida de componentes para optimizar el rendimiento
  • Servicios compartidos para estado entre hermanos (sibling components)
01Básico con input() ⭐
Objetivo
Crear un componente hijo que reciba datos del padre mediante la función input() de Angular 17+.
Enunciado
Crea un componente saludo-usuario que reciba un nombre de usuario y una edad como inputs. El componente debe mostrar un mensaje de saludo personalizado. En el componente padre, renderiza saludo-usuario pasándole distintos valores.
Requisitos
  • Declara nombre = input<string>() y edad = input<number>()
  • Lee los valores en el template con nombre() y edad()
  • El componente padre usa la sintaxis <saludo-usuario nombre="Ana" [edad]="25" />
  • El componente es standalone
Con input() no necesitas el decorador @Input(). Los inputs se leen como funciones: nombre() en el template.
02Eventos con output() ⭐
Objetivo
Notificar al componente padre cuando ocurre un evento dentro del componente hijo usando output().
Enunciado
Crea un componente boton-contador que tenga un botón con un número. Cada vez que se hace clic, el componente hijo emite un evento con el nuevo valor al padre. El padre muestra el contador acumulado.
Requisitos
  • Declara clickeado = output<number>() en el hijo
  • Usa this.clickeado.emit(valor) al hacer clic
  • El padre escucha con (clickeado)="manejarClic($event)"
  • El padre mantiene una signal con el total de clics
output() retorna un EventEmitter. Llama a .emit() con el dato que quieres enviar al padre.
03Two-Way Binding con model() ⭐⭐
Objetivo
Implementar two-way binding entre padre e hijo usando model(), el reemplazo moderno de ngModel a nivel de componente.
Enunciado
Crea un componente campo-tema que permita al usuario seleccionar un tema (claro, oscuro, azul). El padre puede establecer el tema inicial y el hijo notifica al padre cuando cambia. Usa [(tema)] en el template del padre.
Requisitos
  • Declara tema = model<string>('claro') en el hijo
  • El hijo renderiza 3 botones/badges, cada uno con un tema
  • Al seleccionar un tema, actualiza con this.tema.set(nuevoValor)
  • El padre usa [(tema)]="temaActual" y puede leer el tema con temaActual()
model() combina un input y un output en una sola API. El padre puede leer el valor con temaActual() y el hijo puede escribirlo con .set(). El binding [()] sincroniza ambos lados.
04Pasando datos al padre: input() ⭐⭐
Objetivo
Dominar el patrón padre-hijo pasando datos jerárquicos con input() y transformaciones.
Enunciado
Crea un componente tarjeta-perfil que reciba un objeto usuario con nombre, email y foto. El componente debe mostrar la tarjeta con avatar, nombre y email. Crea también un componente lista-perfiles padre que mantenga una lista de usuarios y pase cada uno a un tarjeta-perfil.
Requisitos
  • Define una interfaz Usuario con id, nombre, email, foto
  • tarjeta-perfil recibe usuario = input.required<Usuario>()
  • lista-perfiles tiene una signal con al menos 4 usuarios
  • Renderiza cada tarjeta con @for
  • Usa input.required() para forzar que siempre se pase el dato
input.required() garantiza que el padre siempre pase el dato. Si no se pasa, Angular lanza un error en tiempo de compilación. Es preferible a un input() normal cuando el dato es obligatorio.
05Notificando al padre: output() ⭐⭐
Objetivo
El hijo notifica al padre acciones complejas usando output() con objetos tipados.
Enunciado
Crea un componente lista-tareas con un hijo item-tarea. El hijo emite eventos de: completar (toggle), editar (nuevo texto) y eliminar. El padre maneja el estado de las tareas y muestra estadísticas.
Requisitos
  • Interfaz Tarea: id, texto, completada, fechaCreacion
  • item-tarea recibe una tarea con input()
  • item-tarea emite 3 outputs: toggle = output<number>(), editar = output<{id: number, texto: string}>(), eliminar = output<number>()
  • lista-tareas muestra contadores: total, pendientes, completadas
  • El padre usa @for para renderizar los items
Puedes definir tipos de evento inline en output() o crear interfaces dedicadas. Usa output<{id: number, texto: string}>() para tipos anónimos.
06Content Projection con ng-content ⭐⭐⭐
Objetivo
Usar ng-content para crear componentes contenedores que acepten contenido dinámico del padre.
Enunciado
Crea un componente panel-modal que acepte contenido proyectado para el header, body y footer. El padre define qué contenido va en cada zona usando select con atributos CSS.
Requisitos
  • panel-modal tiene 3 slots: <ng-content select="[panel-header]">, <ng-content select="[panel-body]">, <ng-content select="[panel-footer]">
  • Incluye un botón de cerrar que emita un output()
  • El padre renderiza el modal con contenido personalizado en cada slot
  • Agrega estilos de superposición (overlay) y centrado
ng-content select="[atributo]" selecciona solo los elementos del padre que tengan ese atributo. El contenido del padre se "inyecta" en la posición del ng-content.
07Template Reference Variables ⭐⭐⭐
Objetivo
Usar template reference variables (#ref) para acceder a la instancia de un componente o elemento DOM desde el template.
Enunciado
Crea un componente buscador-ref con un componente hijo campo-busqueda. Desde el padre, usa un template reference variable para acceder al valor del campo de búsqueda y mostrar los resultados en tiempo real.
Requisitos
  • campo-busqueda expone un signal con el valor actual y un método limpiar()
  • El padre usa #miCampo para acceder a la instancia
  • Muestra miCampo.valorActual() en el template del padre
  • Un botón "Limpiar" llama a miCampo.limpiar()
  • Un computed() filtra una lista según el texto de búsqueda
Para que el padre pueda acceder a propiedades del hijo, estas deben ser públicas o estar expuestas vía @ViewChild. Las template reference variables acceden a la instancia del componente y a sus métodos públicos.
08@ViewChild y @ContentChild ⭐⭐⭐⭐
Objetivo
Acceder a componentes hijos y contenido proyectado programáticamente usando @ViewChild y @ContentChild.
Enunciado
Crea un componente editor-color (hijo) con un color picker y un componente panel-configuracion (padre) que lo contiene. El padre usa @ViewChild para acceder al color actual del hijo y @ContentChild para detectar si se proyectó contenido extra.
Requisitos
  • editor-color tiene un signal color y un método getColor()
  • panel-configuracion declare @ViewChild(EditorColor) colorPicker!
  • El padre lee el color con this.colorPicker.color() o .getColor()
  • Usa @ContentChild('extraContent') para detectar contenido proyectado
  • Muestra un mensaje condicional si hay contenido extra
@ViewChild busca en el template del propio componente. @ContentChild busca en el contenido proyectado (<ng-content>). Ambos son undefined hasta el ciclo afterNextRender o ngAfterViewInit.
09Estado compartido con un servicio ⭐⭐⭐⭐
Objetivo
Compartir estado entre componentes hermanos (sibling components) usando un servicio inyectado con signals.
Enunciado
Crea un servicio TemaService con una signal de tema. Crea dos componentes hermanos: selector-tema (cambia el tema) y vista-tema (muestra el tema actual). Ambos usan el mismo servicio para comunicarse.
Requisitos
  • Injectable providedIn: 'root' con tema = signal<string>('oscuro')
  • Método cambiarTema(tema: string) que actualiza la signal
  • selector-tema inyecta el servicio y llama a cambiarTema()
  • vista-tema inyecta el servicio y lee this.temaService.tema()
  • El componente padre renderiza ambos lado a lado
Un servicio con providedIn: 'root' es un singleton: todos los componentes que lo inyectan comparten la misma instancia. Las signals dentro del servicio son reactivas automáticamente en cada componente que las lea.
10Carga diferida con @defer ⭐⭐⭐⭐
Objetivo
Usar @defer para cargar componentes de forma diferida y mejorar el rendimiento inicial de la aplicación.
Enunciado
Crea un componente dashboard-defer que muestre un panel principal siempre visible y 3 paneles pesados (analytics, notificaciones, chat) que se carguen bajo distintas condiciones: al hacer scroll, al pasar el mouse, y al hacer clic.
Requisitos
  • 3 componentes standalone independientes: panel-analytics, panel-notificaciones, panel-chat
  • @defer (on scroll) para analytics
  • @defer (on hover(areasChart)) para notificaciones
  • @defer (on click(botonChat)) para chat
  • Incluye bloques @loading y @placeholder para cada defer
@defer soporta: on viewport, on idle, on interaction, on hover, on immediate, on timer(), when condition. Los bloques @placeholder y @loading muestran contenido mientras se carga.
11Componente reutilizable de tarjeta ⭐⭐⭐⭐⭐
Objetivo
Construir un componente tarjeta (card) completamente reutilizable que combine inputs, outputs y content projection.
Enunciado
Crea un componente ui-card que acepte: título, subtitulo, imagen, badge de estado, y acciones personalizadas via ng-content. Debe ser usable en al menos 3 contextos diferentes: perfil de usuario, producto de tienda, y noticia.
Requisitos
  • titulo = input.required<string>(), subtitulo = input<string>(), imagen = input<string>()
  • badge = input<string>() con alias: input({ alias: 'estado' })
  • Slot <ng-content select="[card-actions]"> para botones de acción
  • Output clickCard = output<void>() que emite al hacer clic en la tarjeta
  • Crea 3 ejemplos de uso: perfil, producto, noticia
Un buen componente reutilizable: 1) valida con input.required() lo obligatorio, 2) tiene defaults sensatos, 3) permite personalización vía ng-content, 4) emite eventos genéricos que el padre decide cómo manejar.
12Data Table completa ⭐⭐⭐⭐⭐
Objetivo
Construir un componente de tabla de datos completo que integre sorting, filtering, acciones por fila y composición con múltiples técnicas de comunicación.
Enunciado
Crea un componente data-table genérico que acepte un array de datos y una configuración de columnas. Debe soportar: ordenamiento por columna, filtro por texto, selección de filas, acciones por fila (editar/eliminar), y exportar como evento. Úsalo para mostrar una lista de empleados.
Requisitos
  • Interfaz Columna: { key, label, sortable, type }
  • datos = input.required<any[]>(), columnas = input.required<Columna[]>()
  • filtro = model<string>() para two-way binding del filtro
  • Outputs: filaEditada = output<any>(), filaEliminada = output<number>(), filasSeleccionadas = output<any[]>()
  • Sorting con signal interna columnaOrden = signal<string>('') y direccion = signal<'asc' | 'desc'>('asc')
  • computed() que combine: datos + filtro + orden para producir las filas visibles
  • Checkbox de selección individual y "seleccionar todo"
  • Slot <ng-content select="[tabla-footer]"> para contenido debajo de la tabla
Diseña la tabla en capas: 1) signal de datos crudos, 2) computed de datos filtrados, 3) computed de datos filtrados + ordenados. Cada capa transforma la anterior. Para la selección, usa un Set de IDs seleccionados como signal interna.
