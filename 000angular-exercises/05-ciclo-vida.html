05 - Ciclo de Vida

Nivel: Intermedio — Módulo 5 de 8

Los hooks de ciclo de vida permiten reaccionar a los diferentes momentos del ciclo de vida de un componente Angular: creación, actualización, destrucción y más. Dominar estos hooks es clave para construir componentes robustos y eficientes.

Conceptos clave

  • constructor — Inyección de dependencias antes de cualquier hook
  • ngOnInit — Inicialización del componente después del primer inputs
  • ngOnChanges — Reacción a cambios en las propiedades de entrada (inputs)
  • ngDoCheck — Detección de cambios personalizada
  • ngAfterContentInit — Contenido proyectado listo
  • ngAfterContentChecked — Contenido proyectado verificado
  • ngAfterViewInit — Vista del componente e hijos listos
  • ngAfterViewChecked — Vista del componente verificada
  • ngOnDestroy — Limpieza antes de destruir el componente
  • implements — Patrón de implementación de interfaces de hooks
  • Orden del ciclo de vida — Secuencia completa de ejecución de hooks
01ngOnInit: inicializar datos del componente ⭐
Objetivo
Comprender cómo usar ngOnInit para inicializar datos de un componente una vez que Angular ha procesado los primeros valores de los inputs.
Enunciado
Crea un componente UserProfile que reciba un nombre de usuario como input y lo formatee para mostrarlo en mayúsculas. La inicialización del nombre formateado debe realizarse dentro de ngOnInit.
Requisitos
  • El componente debe implementar la interfaz OnInit
  • Declara una propiedad @Input() username de tipo string
  • Declara una propiedad displayName que almacene el nombre en mayúsculas
  • En ngOnInit, asigna this.displayName = this.username.toUpperCase()
  • Usa onPush como estrategia de detección de cambios
Recuerda importar OnInit desde @angular/core y agregar implements OnInit en la definición de la clase del componente.
02constructor vs ngOnInit: cuándo usar cada uno ⭐
Objetivo
Entender la diferencia entre el constructor y ngOnInit, y saber en qué situación utilizar cada uno.
Enunciado
Crea un componente DataService que inyecte un servicio LoggerService en el constructor y, en ngOnInit, llame a un método del servicio para registrar que el componente ha sido creado. Agrega logs en ambos métodos para observar el orden de ejecución.
Requisitos
  • Crea un servicio LoggerService con un método log(message: string) que use console.log
  • Inyecta LoggerService en el constructor del componente
  • En el constructor, registra: "Constructor ejecutado"
  • En ngOnInit, registra: "ngOnInit ejecutado"
  • En ngOnInit, llama a this.logger.log('Componente inicializado')
  • El componente debe implementar OnInit
El constructor se ejecuta primero, antes de que Angular procese los inputs. Es el lugar ideal para la inyección de dependencias. ngOnInit se ejecuta después y es ideal para la lógica de inicialización.
03ngOnChanges: reaccionar a cambios de inputs ⭐⭐
Objetivo
Aprender a usar ngOnChanges para detectar y reaccionar a cambios en las propiedades de entrada de un componente.
Enunciado
Crea un componente PriceDisplay que reciba un precio como input. Cuando el precio cambie, el componente debe calcular y almacenar el precio con IVA (21%). Utiliza ngOnChanges para detectar el cambio y recalcular.
Requisitos
  • El componente debe implementar OnChanges
  • Declara @Input() price: number = 0
  • Declara una propiedad priceWithTax: number
  • Implementa ngOnChanges(changes: SimpleChanges) verificando si changes['price'] existe
  • Calcula priceWithTax = price * 1.21
  • Muestra en la plantilla el precio original y el precio con IVA
El objeto SimpleChanges tiene propiedades para cada input que cambió. Cada propiedad contiene previousValue, currentValue y firstChange. Puedes usar changes['price']?.firstChange para evitar cálculos innecesarios en la primera ejecución.
04ngDoCheck: detección de cambios personalizada ⭐⭐
Objetivo
Comprender cuándo y cómo usar ngDoCheck para implementar una lógica de detección de cambios personalizada.
Enunciado
Crea un componente ItemTracker que reciba un objeto item como input. Angular no detecta cambios en propiedades internas de objetos, así que implementa ngDoCheck para comparar manualmente el campo item.name y mostrar un mensaje cuando cambie.
Requisitos
  • El componente debe implementar DoCheck
  • Declara @Input() item: { name: string; count: number }
  • Almacena el valor anterior del nombre en una propiedad previousName
  • En ngDoCheck, compara this.item.name con this.previousName
  • Si el nombre cambió, actualiza previousName y registra el cambio con un contador de cambios
  • Muestra en la plantilla el nombre actual, el nombre anterior y el número total de cambios
ngDoCheck se ejecuta en cada ciclo de detección de cambios, así que evita hacer operaciones pesadas. Es útil para detectar cambios en objetos mutados por referencia que Angular no追踪a automáticamente.
05ngAfterViewInit: acceder a elementos hijos después del render ⭐⭐⭐
Objetivo
Aprender a usar ngAfterViewInit para interactuar con elementos del DOM o componentes hijos una vez que la vista ha sido renderizada completamente.
Enunciado
Crea un componente CanvasChart que contenga un elemento <canvas> en su plantilla. En ngAfterViewInit, obtén la referencia al canvas y dibuja un gráfico de barras simple con datos predefinidos.
Requisitos
  • El componente debe implementar AfterViewInit
  • Declara un @ViewChild('myCanvas') que referencie el elemento canvas
  • En ngAfterViewInit, accede al nativeElement y obtén el contexto 2D
  • Dibuja al menos 3 barras de diferentes alturas con colores diferentes
  • Muestra en la consola un mensaje indicando que la vista está lista
Usa la referencia de template #myCanvas en el HTML para que @ViewChild pueda encontrar el elemento. Ten en cuenta que el canvas debe tener atributos width y height definidos en la plantilla.
06AfterViewInit con ViewChild ⭐⭐⭐
Objetivo
Dominar el uso de @ViewChild junto con AfterViewInit para acceder a componentes hijos y ejecutar métodos en ellos.
Enunciado
Crea un componente hijo MediaPlayer con un método play() y stop(). El componente padre MediaControls debe usar @ViewChild para obtener una referencia al MediaPlayer y controlarlo mediante botones.
Requisitos
  • Crea el componente hijo MediaPlayer con propiedades isPlaying y status
  • Implementa los métodos play() y stop() en MediaPlayer que actualicen el estado
  • En el padre MediaControls, usa @ViewChild(MediaPlayer) para obtener la referencia
  • Implementa AfterViewInit en el padre para verificar que la referencia está disponible
  • Crea botones "Reproducir" y "Detener" que llamen a los métodos del hijo a través de la referencia
  • Muestra el estado actual del reproductor en la plantilla del padre
Asegúrate de que @ViewChild use la clase del componente como selector, no una referencia de template. La referencia al componente hijo solo está disponible después de que Angular ha inicializado la vista, por eso necesitas ngAfterViewInit.
07ngOnDestroy: limpieza y cancelación de suscripciones ⭐⭐⭐
Objetivo
Aprender a implementar ngOnDestroy para liberar recursos y prevenir memory leaks al destruir un componente.
Enunciado
Crea un componente LiveClock que muestre la hora actual y se actualice cada segundo usando setInterval. Implementa ngOnDestroy para cancelar el intervalo cuando el componente se destruya.
Requisitos
  • El componente debe implementar OnDestroy
  • Declara una propiedad currentTime de tipo Date
  • Almacena el ID del intervalo en una propiedad intervalId
  • En ngAfterViewInit (o ngOnInit), inicia un setInterval que actualice currentTime cada segundo
  • En ngOnDestroy, llama a clearInterval(this.intervalId)
  • Registra en consola un mensaje cuando el componente se destruya
Si no cancelas el intervalo, el componente seguirá ejecutándose en memoria aunque ya no sea visible. Esto es un memory leak clásico. Usa una propiedad de clase para almacenar el ID del intervalo.
08OnInit + OnDestroy: patrón de gestión de suscripciones ⭐⭐⭐⭐
Objetivo
Implementar el patrón idiomático de Angular para suscribirse a Observables en ngOnInit y cancelar la suscripción en ngOnDestroy.
Enunciado
Crea un servicio NotificationService que exponga un BehaviorSubject<string>. El componente NotificationPanel debe suscribirse a las notificaciones en ngOnInit y mostrarlas en una lista. La suscripción debe cancelarse en ngOnDestroy.
Requisitos
  • Crea el servicio NotificationService con un BehaviorSubject<string> y un método send(message: string)
  • El componente debe implementar OnInit e OnDestroy
  • Declara una propiedad private destroy$ = new Subject<void>()
  • En ngOnInit, suscríbete usando this.notificationService.getNotifications().pipe(takeUntil(this.destroy$)).subscribe(...)
  • Almacena las notificaciones en un array messages: string[]
  • En ngOnDestroy, emite un valor en destroy$ y llama a destroy$.complete()
El patrón con Subject y takeUntil es más limpio que usar Subscription.unsubscribe() porque funciona con múltiples suscripciones simultáneas. Recuerda inyectar el servicio usando inject() o el constructor.
09ngOnChanges + ngOnInit: flujo de datos padre-hijo ⭐⭐⭐⭐
Objetivo
Comprender la secuencia de ngOnChanges y ngOnInit en un componente hijo, y cómo manejar el flujo de datos desde un componente padre.
Enunciado
Crea un componente padre TaskBoard que gestione una lista de tareas y pase una tarea seleccionada a un componente hijo TaskDetail. El hijo debe usar ngOnChanges para registrar cada cambio de tarea y ngOnInit para la inicialización.
Requisitos
  • Crea un modelo Task con propiedades id, title, description y completed
  • El padre TaskBoard mantiene un array de tareas y una tarea seleccionada
  • El padre tiene botones para seleccionar diferentes tareas y pasa la tarea seleccionada al hijo con [task]="selectedTask"
  • El hijo TaskDetail implementa OnChanges e OnInit
  • En ngOnChanges, el hijo almacena un historial de tareas recibidas
  • En ngOnInit, el hijo muestra un mensaje de inicialización con el título de la tarea actual
  • Muestra en la plantilla del hijo el detalle de la tarea y un log de las tareas anteriores
ngOnChanges se ejecuta antes que ngOnInit solo en la primera carga. Después, ngOnChanges se ejecuta en cada cambio del input mientras que ngOnInit solo se ejecuta una vez. Esto es fundamental para entender el flujo de datos.
10AfterContentInit: trabajar con contenido proyectado ⭐⭐⭐⭐
Objetivo
Aprender a usar ngAfterContentInit para acceder al contenido proyectado con ng-content una vez que ha sido inicializado.
Enunciado
Crea un componente contenedor CollapsiblePanel que proyecte contenido. Usa @ContentChild para obtener una referencia al contenido proyectado y ngAfterContentInit para medir o inspeccionar dicho contenido.
Requisitos
  • El componente CollapsiblePanel debe tener un encabezado con título y un botón para colapsar/expandir
  • Usa <ng-content> para proyectar contenido en el cuerpo del panel
  • Implementa AfterContentInit
  • Declara @ContentChild('panelContent') contentEl: ElementRef para obtener una referencia al contenido
  • En ngAfterContentInit, verifica que contentEl exista y muestra en consola la cantidad de nodos hijos del contenido
  • Crea un componente padre que use CollapsiblePanel y proyecte un párrafo con una referencia de template #panelContent
El contenido proyectado con ng-content no está disponible en ngAfterViewInit porque se procesa después de la vista del componente pero antes de la vista de los hijos. Por eso existe ngAfterContentInit.
11Orden del ciclo de vida: secuencia completa ⭐⭐⭐⭐⭐
Objetivo
Visualizar y comprender el orden completo de ejecución de todos los hooks de ciclo de vida en Angular.
Enunciado
Crea un componente padre LifecycleDemo y un hijo LifecycleChild. El padre tiene un botón para incrementar un contador (trigger de detección de cambios). Ambos componentes deben implementar TODOS los hooks de ciclo de vida y registrar cada ejecución con un timestamp en un array compartido.
Requisitos
  • Crea un servicio LifecycleLogService con un array logs: { hook: string; component: string; time: string }[] y un método add(hook, component)
  • Ambos componentes implementan: OnChanges, OnInit, DoCheck, AfterContentInit, AfterContentChecked, AfterViewInit, AfterViewChecked, OnDestroy
  • Cada hook en ambos componentes llama a logService.add('nombreDelHook', 'Padre' o 'Hijo')
  • El componente padre muestra en tiempo real la lista de logs ordenados cronológicamente
  • Un botón en el padre incrementa un contador que se pasa como input al hijo para triggerar ngOnChanges
  • Implementa un botón "Limpiar logs" y un botón "Destruir hijo" (usando *ngIf) para observar los hooks de destrucción
El orden esperado en la creación es: constructor → ngOnChanges → ngOnInit → ngDoCheck → ngAfterContentInit → ngAfterContentChecked → ngAfterViewInit → ngAfterViewChecked. En actualizaciones: ngOnChanges → ngDoCheck → ngAfterContentChecked → ngAfterViewChecked.
12Patrón práctico: componente con auto-refresh y limpieza de temporizadores ⭐⭐⭐⭐⭐
Objetivo
Construir un componente completo que combine múltiples hooks de ciclo de vida en un patrón práctico y realista: un panel de métricas con auto-refresh.
Enunciado
Crea un componente MetricsDashboard que simule un panel de métricas en tiempo real. El componente debe cargar datos iniciales, configurar un auto-refresh cada N segundos, limpiar suscripciones al destruirse, reaccionar a cambios del intervalo de refresco y acceder a un elemento hijo después de la vista.
Requisitos
  • Crea un servicio MetricsService que exponga un método getMetrics() retornando un Observable con datos simulados (CPU, RAM, disco) y un método setInterval(ms) que controle la frecuencia de emisión
  • Implementa OnChanges, OnInit, AfterViewInit, OnDestroy en el componente
  • Declara un input @Input() refreshInterval: number = 5000 para controlar el intervalo de refresco
  • En ngOnInit, suscríbete al observable de métricas usando el patrón takeUntil(destroy$)
  • En ngOnChanges, cuando cambie refreshInterval, actualiza el intervalo en el servicio
  • Usa @ViewChild con una referencia a un elemento de la plantilla (por ejemplo, un indicador de estado) y en ngAfterViewInit accede a él para cambiar su estilo
  • En ngOnDestroy, completa el Subject destroy$ y registra un mensaje de limpieza
  • La plantilla debe mostrar: un indicador de estado visual, las 3 métricas en tarjetas, el intervalo de refresco actual y un timestamp de la última actualización
Este ejercicio integra todo lo aprendido. Piensa en la separación de responsabilidades: el servicio maneja la fuente de datos, el componente gestiona el ciclo de vida, y los hooks coordinan la creación, actualización y destrucción de recursos. El patrón Subject + takeUntil es esencial para evitar memory leaks.
