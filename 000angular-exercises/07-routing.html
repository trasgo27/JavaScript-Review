07 - Routing

Nivel: Avanzado

El sistema de rutas de Angular permite crear aplicaciones de una sola página (SPA) con navegación fluida entre vistas. En este módulo aprenderás a configurar rutas, usar parámetros, cargar componentes de forma lazy, y proteger rutas con guards. La sintaxis es de Angular 17+ con funciones y loadComponent.

Conceptos clave

  • provideRouter — Proveedor de configuración de rutas en app.config.ts
  • Routes — Array de definiciones de ruta
  • RouterLink — Directiva para enlaces de navegación declarativa
  • RouterLinkActive — Directiva para resaltar la ruta activa
  • ActivatedRoute — Servicio para acceder a los datos de la ruta actual
  • Router.navigate() — Navegación programática con opciones
  • Router.navigateByUrl() — Navegación programática por URL absoluta
  • :id — Parámetros de ruta dinámicos
  • queryParams — Parámetros de consulta en la URL
  • children — Rutas anidadas (rutas hijas)
  • ** — Ruta comodín (wildcard) para páginas 404
  • loadComponent — Carga perezosa de un componente individual
  • loadChildren — Carga perezosa de un módulo o grupo de rutas
  • CanActivate — Guard que controla el acceso a una ruta
  • CanDeactivate — Guard que controla la salida de una ruta
  • Guards funcionales — Guards basados en funciones flecha en Angular 17+
01Configuración básica con provideRouter ⭐⭐
Objetivo
Configurar el sistema de rutas de Angular desde cero en una aplicación standalone.
Enunciado
Crea una aplicación standalone con dos componentes: HomeComponent y AboutComponent. Configura el enrutador en app.config.ts usando provideRouter y define dos rutas: una para la ruta raíz / que muestre HomeComponent, y otra para /about que muestre AboutComponent. En app.component.ts, añade el <router-outlet> para renderizar el componente activo.
Requisitos
  • Usar provideRouter(routes) en el array de providers de app.config.ts
  • Definir el array de rutas con Routes
  • Cada ruta usa component (no loadComponent)
  • El componente raíz tiene <router-outlet>
  • Ambos componentes son standalone
Recuerda importar provideRouter desde @angular/router y añadirlo al array de providers en bootstrapApplication.
02RouterLink y RouterLinkActive ⭐⭐
Objetivo
Crear una barra de navegación con enlaces declarativos y resaltado de la ruta activa.
Enunciado
Añade al componente raíz una barra de navegación con tres enlaces: Inicio (/), Acerca de (/about) y Contacto (/contact). Usa la directiva routerLink para la navegación y routerLinkActive para aplicar una clase CSS active al enlace de la ruta actual.
Requisitos
  • Usar [routerLink]="['/'] y similar para cada ruta
  • Usar routerLinkActive="active" en cada enlace
  • Añadir un estilo CSS para la clase .active que cambie el color o fondo
  • Los enlaces deben usar <a> nativos, no botones
  • Crear los componentes destino si no existen
La directiva routerLinkActive acepta un string con clases CSS o un objeto [routerLinkActiveOptions]="{ exact: true }" para controlar la coincidencia exacta en la ruta raíz.
03Navegación con Router service ⭐⭐⭐
Objetivo
Navegar programáticamente entre rutas usando el servicio Router.
Enunciado
Crea un componente DashboardComponent con tres botones: "Ir a Perfil", "Ir a Configuración" y "Ir a Inicio". Al hacer clic en cada botón, navega a la ruta correspondiente usando router.navigate(). Añade también un botón "Ir por URL" que use router.navigateByUrl('/') para volver al inicio. Muestra un mensaje en consola cada vez que se produce una navegación.
Requisitos
  • Inyectar Router desde @angular/router
  • Usar this.router.navigate(['/ruta']) para navegación programática
  • Usar this.router.navigateByUrl('/') al menos una vez
  • Usar console.log para registrar cada navegación
  • Crear los componentes destino necesarios
navigate() acepta un array de segmentos de URL y un objeto de opciones como { queryParams: {...} }. navigateByUrl() acepta un string con la URL completa.
04Parámetros de ruta con :id ⭐⭐⭐
Objetivo
Leer parámetros dinámicos de la URL para mostrar contenido específico.
Enunciado
Crea una ruta /user/:id que apunte a un UserDetailComponent. Este componente debe leer el parámetro id de la URL usando ActivatedRoute y mostrar un mensaje como "Mostrando perfil del usuario #42". Añade una lista de enlaces en la página principal que usen routerLink para navegar a diferentes usuarios (por ejemplo: usuario 1, 2 y 3).
Requisitos
  • Definir la ruta { path: 'user/:id', component: UserDetailComponent }
  • Inyectar ActivatedRoute en el componente
  • Leer el parámetro con this.route.snapshot.paramMap.get('id')
  • También usar la versión reactiva con this.route.paramMap.subscribe(...)
  • Crear enlaces routerLink tipo ['/user', 1]
Usa snapshot.paramMap para leer el parámetro una sola vez, o paramMap (Observable) cuando el componente se reutiliza y el parámetro cambia sin destruirlo.
05Parámetros de consulta (Query Parameters) ⭐⭐⭐
Objetivo
Usar query parameters para filtros, paginación y estado sin afectar la ruta base.
Enunciado
Crea un componente ProductListComponent que muestre una lista ficticia de productos. Implementa un sistema de filtros donde al seleccionar una categoría se añada un queryParams ?category=electronics a la URL. Usa activatedRoute.queryParamMap para leer el filtro y mostrar solo los productos de esa categoría. Añade un botón de "Limpiar filtros" que navegue sin query params.
Requisitos
  • Usar router.navigate con la opción { queryParams: { category: 'value' } }
  • Leer los query params con this.route.queryParamMap.subscribe(...)
  • Filtrar la lista de productos según el query param
  • Preservar otros query params al cambiar de categoría con queryParamsHandling: 'merge'
  • Botón para limpiar: router.navigate([], { queryParams: {} })
La opción queryParamsHandling admite 'merge' (combinar) o 'preserve' (mantener los actuales) para no perder parámetros existentes.
06Rutas anidadas (child routes) ⭐⭐⭐⭐
Objetivo
Organizar la navegación interna de una sección usando rutas hijas.
Enunciado
Crea una sección /settings con un layout propio que contenga una barra lateral con enlaces a /settings/profile, /settings/security y /settings/notifications. Cada sub-ruta debe ser hija de /settings usando la propiedad children en la definición de ruta. El componente padre SettingsComponent debe incluir un <router-outlet> para renderizar los componentes hijos.
Requisitos
  • Usar la propiedad children: [...] en la definición de /settings
  • El componente padre tiene su propio <router-outlet>
  • Cada ruta hija tiene su componente standalone
  • Usar routerLink con rutas relativas: ['profile'] (sin barra inicial)
  • Añadir routerLinkActive en la barra lateral
Las rutas relativas en routerLink dentro de rutas anidadas no llevan / al inicio. Por ejemplo, ['profile'] se resuelve como /settings/profile.
07Ruta comodín (Wildcard 404) ⭐⭐⭐
Objetivo
Mostrar una página de "no encontrado" cuando la URL no coincide con ninguna ruta definida.
Enunciado
Crea un componente NotFoundComponent que muestre un mensaje amigable tipo "404 - Página no encontrada" con un enlace para volver al inicio. Añade una ruta comodín ** al final del array de rutas que apunte a este componente. Asegúrate de que funcione tanto para rutas inexistentes como para rutas anidadas mal formadas.
Requisitos
  • La ruta { path: '**', component: NotFoundComponent } debe ser la última del array
  • El componente muestra un mensaje de error 404
  • Incluye un enlace routerLink para volver a /
  • Funciona con cualquier URL inexistente, como /abcdefg
  • Crear el componente con estilos apropiados para una página de error
La ruta comodín ** coincide con cualquier segmento de URL que no haya sido capturado por rutas anteriores. Por eso siempre debe ir al final del array de rutas.
08Lazy loading con loadComponent ⭐⭐⭐⭐
Objetivo
Cargar componentes bajo demanda para mejorar el rendimiento de carga inicial.
Enunciado
Reconfigura una ruta existente (por ejemplo, /about) para que su componente se cargue de forma perezosa usando loadComponent en lugar de component. El componente no debe importarse estáticamente en el archivo de rutas. Crea el componente en un archivo separado con la anotación export default. Verifica que el chunk separado se carga en la pestaña "Network" del navegador solo cuando se navega a esa ruta.
Requisitos
  • Usar loadComponent: () => import('./path').then(m => m.default)
  • No usar la propiedad component en la misma definición de ruta
  • El componente exportado debe tener export default
  • Verificar en la pestaña Network del navegador que se genera un chunk JS separado
  • La navegación funciona igual que con carga estática
La función loadComponent usa dynamic import. El componente exportado con export default se extrae con .then(m => m.default).
09Lazy loading con loadChildren ⭐⭐⭐⭐⭐
Objetivo
Cargar un grupo completo de rutas hijas de forma perezosa usando loadChildren.
Enunciado
Crea un archivo de rutas separado admin.routes.ts que exporte un array de rutas para una sección de administración (por ejemplo: /admin/dashboard, /admin/users, /admin/settings). En el archivo principal de rutas, carga este archivo de forma perezosa usando loadChildren. Crea los componentes correspondientes. Verifica que al navegar a cualquier ruta /admin/* se carga un chunk JS independiente.
Requisitos
  • Crear archivo admin.routes.ts con export default Routes
  • Usar loadChildren: () => import('./admin.routes').then(m => m.default)
  • Las rutas hijas son relativas (sin /admin al inicio)
  • Crear al menos 3 componentes para la sección admin
  • Verificar la carga lazy en la pestaña Network del navegador
Con loadChildren las rutas hijas se definen sin el prefijo de la ruta padre. La ruta padre (/admin) se concatena automáticamente con cada ruta hija.
10Guard CanActivate ⭐⭐⭐⭐⭐
Objetivo
Proteger rutas para que solo usuarios autenticados puedan acceder a ellas.
Enunciado
Crea un guard funcional authGuard que verifique si el usuario está autenticado (simula esto con un BehaviorSubject<boolean> en un servicio). Si no está autenticado, redirige a la ruta /login. Aplica este guard a la ruta /dashboard usando canActivate. Crea también un componente LoginComponent con un botón que simule el login.
Requisitos
  • Crear el guard como función: export const authGuard: CanActivateFn = (route, state) => { ... }
  • Inyectar el servicio de auth con inject(AuthService)
  • Si no autenticado: router.createUrlTree(['/login']) o return ['/login']
  • Si autenticado: return true
  • Usar canActivate: [authGuard] en la definición de ruta
  • Importar el guard directamente en el array canActivate
En Angular 17+ los guards funcionales son funciones con la firma CanActivateFn. Se usan inject() en lugar del constructor para inyectar servicios. El guard puede retornar true, false, o un UrlTree.
11Guard CanDeactivate (cambios sin guardar) ⭐⭐⭐⭐⭐
Objetivo
Evitar que el usuario navegue fuera de una página si tiene cambios sin guardar.
Enunciado
Crea un componente EditProfileComponent con un formulario (un simple campo de texto). Cuando el usuario modifique el campo, se marca como "cambiado". Crea un guard funcional unsavedChangesGuard que use CanDeactivateFn y verifique si hay cambios pendientes. Si los hay, muestra un confirm() preguntando si desea salir. Si el usuario acepta, permite la navegación; si no, la cancela.
Requisitos
  • Crear una interfaz CanComponentDeactivate con un método canDeactivate(): boolean | Observable<boolean>
  • El componente implementa esta interfaz
  • El guard verifica si el componente tiene el método y lo llama
  • Usar confirm('¿Seguro que quieres salir?') para la confirmación
  • Aplicar el guard con canDeactivate: [unsavedChangesGuard]
  • Mostrar un indicador visual cuando el formulario tiene cambios
El guard CanDeactivateFn recibe el componente actual como primer parámetro, lo que permite acceder a sus propiedades. Define una interfaz común para que cualquier componente con cambios sin guardar pueda ser detectado.
12Aplicación multi-página completa ⭐⭐⭐⭐⭐
Objetivo
Integrar todos los conceptos de routing en una aplicación completa con navegación, páginas de detalle, rutas anidadas, lazy loading y guards.
Enunciado
Crea una aplicación de gestión de tareas con las siguientes secciones:
  • Home (/) — Página de bienvenida con enlaces a las secciones
  • Tareas (/tasks) — Lista de tareas con query param ?status=pending|done para filtrar. Al hacer clic en una tarea, navega a /tasks/:id
  • Detalle de tarea (/tasks/:id) — Muestra el detalle completo de la tarea
  • Panel Admin (/admin/*) — Rutas anidadas lazy-loaded para admin/dashboard y admin/users
  • Login (/login) — Página de login para simular autenticación
  • 404 — Ruta comodín para rutas no encontradas
Requisitos
  • Barra de navegación con routerLink y routerLinkActive
  • Lazy loading con loadComponent para las páginas principales
  • Lazy loading con loadChildren para la sección admin
  • Ruta /tasks/:id con ActivatedRoute para leer el ID
  • Query params ?status= para filtrar la lista de tareas
  • Guard canActivate funcional en las rutas de admin
  • Guard canDeactivate funcional en un formulario de edición de tarea
  • Ruta comodín ** como última ruta del array
  • Los guards usan la sintaxis funcional con inject()
  • Todos los componentes son standalone
Organiza las rutas en archivos separados (por ejemplo, admin.routes.ts). Usa un servicio de autenticación simple con BehaviorSubject<boolean> para el estado de login. Para los datos de tareas, puedes usar un array estático en un servicio.
