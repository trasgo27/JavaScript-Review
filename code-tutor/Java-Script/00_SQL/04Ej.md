# Debugging Report: 04Ej.js

## Task 1: Top 3 most expensive products

Original broken query:

```sql
SELECT * product.name AS producto, product.price AS precio FROM product ORDER BY ? DESCENDING LIMIT ?;
```

| Error | Problem | Fix |
|---|---|---|
| `SELECT * product.name` | Stray `*` after SELECT — selects all columns AND a specific column | Remove `*` |
| `FROM product` | Wrong table name (should be `product`s) | `FROM products` |
| `DESCENDING` | Invalid SQL keyword | `DESC` |
| `ORDER BY ?` | Column names cannot be parameterized with `?` placeholders | `ORDER BY price DESC` |
| `.all(price, 3)` | `price` is an undefined variable; parameters don't work for identifiers | Remove parameters |

Correct query:

```sql
SELECT name AS producto, price AS precio FROM products ORDER BY price DESC LIMIT 3
```

## Task 4: Average price per category

Original broken query:

```sql
SELECT products.price * products.quantity AS precio_medio FROM products GROUP BY category
```

| Error | Problem | Fix |
|---|---|---|
| `products.price * products.quantity` | `quantity` column doesn't exist; wrong calculation | Use `AVG(price) AS avg_price` |
| Only one column selected | Task asks for average price AND product count per category | Add `COUNT(*) AS total_items` |

### Detailed walkthrough

**What it should do:** Group all products by their category, and for each group, show the category name, the average price within that category (`avg_price`), and the total number of products in that category (`total_items`).

**Flow of the correct query:**
```
FROM products          → 9 rows
GROUP BY category      → 4 groups: books (2), clothing (2), electronics (3), food (2)
SELECT category        → the group label
       AVG(price)      → average of all prices in that group
       COUNT(*)        → how many rows are in that group
```

**Execution with real data:**

| Category | Products | AVG(price) | COUNT(*) |
|---|---|---|---|
| books | 45, 35 | **40** | **2** |
| clothing | 30, 60 | **45** | **2** |
| electronics | 1200, 800, 25 | **675** | **3** |
| food | 15, 10 | **12.5** | **2** |

**Why `products.price * products.quantity` is wrong:**
- The table has no `quantity` column — it's called `stock` (line 27). Even if you used `stock`, `price * stock` computes "total inventory value per product type," which is not an average of anything.
- `AVG(price)` is the correct aggregate function — it adds up all prices in a group and divides by the count of rows.

Correct query:

```sql
SELECT category, AVG(price) AS avg_price, COUNT(*) AS total_items FROM products GROUP BY category
```

## Task 5: High value categories

Original broken query:

```sql
SELECT * (products.price * product.quantity) AS avg_price FROM products GROUP BY categories WHERE avg_price > 50
```

| Error | Problem | Fix |
|---|---|---|
| `SELECT * (...)` | Invalid syntax | Use `SELECT category, AVG(price) AS avg_price` |
| `product.quantity` | Column doesn't exist | Remove |
| `GROUP BY categories` | Column name is `category` (singular) | `GROUP BY category` |
| `WHERE avg_price > 50` | Can't filter aggregates with `WHERE` | Use `HAVING AVG(price) > 50` |

### Detailed walkthrough

**What it should do:** After grouping products by category, calculate each category's average price, but only show categories where that average exceeds 50. This is "post-group filtering" — filter groups, not rows.

**Flow of the correct query:**
```
FROM products          → 9 rows from the table
GROUP BY category      → collapses into 4 groups: books, clothing, electronics, food
SELECT category,       → for each group, keep the category name
       AVG(price)      → calculate average price within the group
HAVING AVG(price) > 50 → keep only groups where the average > 50
```

**Execution with real data:**

| Category | Products | Avg Price | > 50? |
|---|---|---|---|
| books | JavaScript Book (45), SQL Guide (35) | (45+35)/2 = **40** | ❌ |
| clothing | Shirt (30), Jeans (60) | (30+60)/2 = **45** | ❌ |
| electronics | Laptop (1200), Phone (800), Mouse (25) | (1200+800+25)/3 = **675** | ✅ |
| food | Pizza (15), Salad (10) | (15+10)/2 = **12.5** | ❌ |

Only `electronics` passes.

**Why `WHERE` vs `HAVING` matters:**
- `WHERE` runs **before** `GROUP BY` — it filters individual rows before any grouping happens. At that point, `avg_price` doesn't exist yet (it's computed during aggregation).
- `HAVING` runs **after** `GROUP BY` — it filters groups after aggregation is complete. This is where you can reference aggregate results like `AVG(price)`.
- This is the single most important conceptual difference between `WHERE` and `HAVING`.

**Key distinction between Task 4 and Task 5:**
- Task 4 shows **all** categories with their stats (no filtering after `GROUP BY`).
- Task 5 starts from the same grouping but then **filters the groups** using `HAVING` to only show those with `AVG(price) > 50`.

Correct query:

```sql
SELECT category, AVG(price) AS avg_price FROM products GROUP BY category HAVING AVG(price) > 50
```
