## Corrección sugerida

2. **`.map()`** para transformar los datos limpios.

You made a very common mistake here regarding how `.filter()` works compared to `.map()`.

Remember the core difference between these two array tools:

* **`.map()`** expects you to return a **new object** or value. It reshapes data.
* **`.filter()`** doesn't care about shapes or objects; it only cares about a **Boolean (`true` or `false`)**. If the condition returns `true`, the original item stays in the array. If it returns `false`, the item is thrown away.

Right now, your `.filter()` is returning an object `{ orderId: ..., dispatchDate: ... }`. Because an object always counts as a "truthy" value in JavaScript, your filter isn't actually dropping any of the broken rows!

Also, watch out for this line: `d.orderId.startsWith('id').toLowerCase()`. Since `.startsWith()` returns a boolean (`true`/`false`), trying to call `.toLowerCase()` on a boolean will crash your code with an error.

To filter properly, you need to combine your conditions into a single statement that evaluates to `true` or `false`:

## 🚨 Trap: `.toFixed()` Returns a String, Not a Boolean

This is a really creative use of the Nullish Coalescing operator (`??`), but it exposes a massive, hidden trap in how JavaScript handles truth values!

If you run this code, **every single row will still pass through your filter.** Let's break down exactly why this happens, because it's a favorite topic for exam questions.

### The Trap: `.toFixed()` Returns a String, Not a Boolean

Inside a `.filter()`, JavaScript expects your `return` statement to yield a boolean: `true` or `false`. If you return something else, JavaScript forces it into a boolean context (evaluating it as "truthy" or "falsy").

Let's look at what your code does for the broken row (`transitDays: null`):

1. `d.transitDays ?? 99` correctly falls back to `99`.
2. `(99).toFixed(0)` converts that number into the text string **`"99"`**.
3. Inside a condition, **any non-empty string is considered "truthy"**.

Because `"99"` is truthy, JavaScript thinks you meant `true`, and it allows the broken record to pass right through!

### How to write it so it actually filters

If your goal is to eliminate records where `transitDays` is missing (`null` or `undefined`), you don't need `.toFixed()` at all. You just want to check if the value exists:

```javascript
const filtro1 = warehouseDispatches.filter((d) => {
    // This returns true ONLY if transitDays is not null and not undefined
    return d.transitDays ?? false; 
});
```

Or even simpler and more standard:

```javascript
const filtro1 = warehouseDispatches.filter((d) => {
    return d.transitDays !== null;
});
```
