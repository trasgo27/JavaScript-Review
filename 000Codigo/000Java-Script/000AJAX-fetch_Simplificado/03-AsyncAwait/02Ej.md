## Conceptos Clave

| Mal (Callback Hell) | Bien (Async/Await) |
|---------------------|-------------------|
| `.then().then().then()` | `await` lineal |
| Funciones async innecesarias | Código directo dentro del `async` |
| Mezclar paradigmas | Solo `async/await` o solo `.then()` |
| Variables globales accidentales | `const`/`let` en cada asignación |

### Flujo correcto:

```javascript
// 1. Fetch retorna Response
const res = await fetch(url);

// 2. .json() retorna Promise que resuelve el objeto
const data = await res.json();

// 3. Ahora data es un objeto JavaScript utilizable
console.table(data);
```

## Referencia: `try/catch` vs `.then().catch()`

| | `try/catch` | `.then().catch()` |
|---|---|---|
| **Uso** | Con `async/await` | Con Promesas |
| **Estilo** | Síncrono (más legible) | Encadenado (fluido) |
| **Errores captura** | Solo de `await` | Solo de `.then()` anterior |

### Ejemplo comparativo

```javascript
// ✅ async/await + try/catch
async function getData() {
  try {
    const res = await fetch(url);
    const data = await res.json();
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}

// ✅ Promesas + .then().catch()
function getData() {
  fetch(url)
    .then(res => res.json())
    .then(data => console.log(data))
    .catch(error => console.error(error));
}
```

### Diferencia clave

```javascript
// try/catch captura errores de CUALQUIER await en el bloque
try {
  const a = await fetch(url1);  // Si falla aquí...
  const b = await fetch(url2);  // ...este código NO se ejecuta
} catch (e) {
  // Se ejecuta
}

// .catch() solo captura errores del .then() ANTERIOR
fetch(url1)
  .then(res => fetch(url2))  // Si falla aquí...
  .then(data => console.log(data))
  .catch(e) {
    // Se ejecuta (captura errores de la cadena)
  }
```

### Recomendación

Usa `async/await` + `try/catch` para código moderno — es más legible y fácil de debuggear.
