## Respuesta: ¿Con try o sin try?

**Con `try`** es mejor porque:
- Si el fetch falla (URL inválida, sin internet, etc.), el código **no se rompe**
- Puedes mostrar un error amigable al usuario
- El programa **continúa ejecutándose**

**Sin `try`**:
- Si hay error, **toda la función se detiene**
- El error aparece en consola pero no hay control

```javascript
// ✅ Recomendado: con try/catch
try {
  const fotos = await fetchFotos();
  console.table(fotos);
} catch (error) {
  console.error('No se pudieron cargar las fotos:', error.message);
}
```

## Código Corregido (con try/catch)

```javascript
console.log('=== Ejercicio 04: Debugging async/await ===');

async function obtenerDatos() {
  try {
    // TAREA 1: Obtener usuario
    console.log('--- Tarea 1 ---');
    const respUsuario = await fetch('https://jsonplaceholder.typicode.com/users/1');
    const usuario = await respUsuario.json();
    console.log('Usuario:', usuario);

    // TAREA 2: Obtener albumes del usuario
    console.log('--- Tarea 2 ---');
    const respAlbumes = await fetch(
      'https://jsonplaceholder.typicode.com/albums?userId=' + usuario.id
    );
    const albumes = await respAlbumes.json();
    console.log('Albumes:', albumes);

    // TAREA 3: Obtener fotos del primer album
    console.log('--- Tarea 3 ---');
    const primerAlbum = albumes[0];
    const respFotos = await fetch(
      'https://jsonplaceholder.typicode.com/photos?albumId=' + primerAlbum.id
    );
    const fotos = await respFotos.json();
    console.log('Fotos del álbum "' + primerAlbum.title + '":', fotos);
    console.table(fotos);

    // TAREA 4: Mostrar resumen
    console.log('--- Tarea 4 ---');
    console.log(usuario.name + ' tiene ' + albumes.length + ' albumes');

  } catch (error) {
    console.error('Error:', error.message);
  }
}

obtenerDatos();
```
