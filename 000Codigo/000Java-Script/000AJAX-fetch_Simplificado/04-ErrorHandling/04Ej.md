# Code Review: 04Ej.js — Wrapper fetchJSON seguro

## Bugs Found in `fetchJSON`

### 1. `return` instead of `throw` (line 34)
The function returns a `TypeError` object as a resolved promise value instead of throwing it.
Callers using `.catch()` will never receive the error.
```js
// Wrong
return new TypeError('Error HTTP ...');

// Correct
throw new Error('Error HTTP ...');
```

### 2. Invalid `datos.ok` check (lines 37-39)
JSONPlaceholder responses don't have an `ok` property on the body.
`datos.ok` is always `undefined` (falsy), so this block runs on every valid response,
incorrectly returning a TypeError. This check should be removed entirely.

### 3. `TypeError` vs `Error` (line 34)
HTTP errors should use `new Error(...)`. `TypeError` is reserved for type-mismatch
scenarios (like network failures caught by fetch), not application-level HTTP errors.

## Second Review — After Debug

### 4. Dead code: `if(!datos)` check (lines 37-39)
`respuesta.json()` always resolves to a truthy object, so `!datos` is never true.
This block is unreachable dead code and should be removed.

### 5. Invalid properties in error message (line 38)
Even if the block ran, `datos.status` and `datos.statusText` are HTTP-level properties
on the Response object — they don't exist on the parsed JSON body.
The error message would read `"Error JASON undefined: undefined"`.
