## Debug TAREA 2 — `getAuthHeaders()`

### ¿Qué debería hacer la función?

`getAuthHeaders()` solo necesita:
1. **Leer** un token de `localStorage`
2. **Retornar** `{ 'Authorization': token }`

Sin fetch, sin POST, sin async, sin parámetros.

### Bugs encontrados

| # | Línea | Bug | Severidad |
|---|-------|-----|-----------|
| 1 | 54-71 | Sobrecomplejidad — hace un POST con fetch cuando solo debe leer localStorage | 🔴 Crítico |
| 2 | 66 | `authentication` no es un header válido — debe ser `Authorization` | 🔴 Crítico |
| 3 | 65 | `textContent` no es un header — es propiedad DOM | 🔴 Crítico |
| 4 | 70 | Retorna un `Response` en vez de un objeto headers | 🔴 Alto |
| 5 | 74-77 | Callback `respuesta` nunca se invoca + log muestra la función | 🟡 Medio |
| 6 | 54 | `async` innecesario — localStorage es síncrono | 🟡 Medio |

### Bug #1 — Sobrecomplejidad brutal (líneas 54-71)

```js
// ❌ ANTES — hace todo menos lo que debe
async function getAuthHeaders(tokenLlave) {
  const miToken = localStorage.getItem(tokenLlave);
  const miPost = { userId: 10, title: 'Salva Post', body: 'Este es el post de Salva' };
  const bodyS = JSON.stringify(miPost);
  const respuesta = await fetch(`${API}/posts`, {
    method: 'POST',
    headers: { ... },
    body: bodyS
  });
  return respuesta;
}

// ✅ DESPUÉS — solo lee y retorna
function getAuthHeaders() {
  const token = localStorage.getItem('tokenAutenticacion');
  return { 'Authorization': token };
}
```

### Bug #2 — Header `authentication` no existe (línea 66)

```js
// ❌ ANTES
authentication: miToken

// ✅ DESPUÉS
'Authorization': miToken
```

`authentication` no es un header HTTP válido. El header estándar para tokens es **`Authorization`**.

### Bug #3 — `textContent` no es un header (línea 65)

```js
// ❌ ANTES
textContent: 'application/json;UTF-8'

// ✅ DESPUÉS (solo si necesitas Content-Type)
'Content-Type': 'application/json; charset=UTF-8'
```

`textContent` es una propiedad del DOM, no un header HTTP.

### Bug #4 — Retorna un `Response` en vez de headers (línea 70)

```js
// ❌ ANTES
return respuesta;  // ← Response object del fetch

// ✅ DESPUÉS
return { 'Authorization': token };  // ← objeto headers plano
```

### Bug #5 — Callback nunca se invoca (líneas 74-77)

```js
// ❌ ANTES — define pero nunca llama
const respuesta = () => {
  getAuthHeaders('tokenLlave');
  console.log(`Este es miToken ${respuesta}`);
};

// ✅ DESPUÉS — llama directamente
const headers = getAuthHeaders();
console.log('Headers generados:', headers);
```

### Bug #6 — `async` innecesario (línea 54)

`localStorage.getItem()` es síncrono. Agregar `async` hace que la función retorne una Promise en vez de un objeto, rompiendo `getAuthHeaders().Authorization`.

### Código corregido de `hacerEj2()`

```js
function hacerEj2() {
  console.log('\n--- Tarea 2: getAuthHeaders ---');

  function getAuthHeaders() {
    const token = localStorage.getItem('tokenAutenticacion');
    return { 'Authorization': token };
  }

  const headers = getAuthHeaders();
  console.log('Headers generados:', headers);
}
```

### Lección clave

> **Una función debe hacer exactamente una cosa.** `getAuthHeaders()` se llama **get** **Auth Headers**. No se llama "hacer POST al servidor con un body y un token". Cuando veas que una función crece y hace cosas que no están en su nombre, **recorta**. La complejidad viene después — en TAREA 3 usarás `getAuthHeaders()` dentro de un `fetch()` real.

### Lección clave: async/await no es decoración

> **`async/await` solo tiene sentido cuando la función interna retorna una Promise.**

| API Síncrona | API Asíncrona (Promise) |
|---|---|
| `localStorage.getItem()` | `fetch()` |
| `localStorage.setItem()` | `fs.readFile()` (Node) |
| `JSON.parse()` | `crypto.subtle.importKey()` |
| **No necesita async/await** | **Sí necesita async/await** |

**Regla de oro:** Antes de escribir `async`, pregúntate: *"¿Alguna función dentro retorna una Promise?"*. Si la respuesta es no, `async` sobra.

### Lección clave

> **Variable Shadowing: el bug silencioso.** Cuando declaras `const post` dentro de una función que ya tiene un parámetro `post`, JavaScript **no lanza error** — simplemente bloquea el acceso al parámetro original. Usa `payload`, `bodyData`, `postBody`.

### Fix del bug #2 — Spread para desanidar

```js
// ❌ {aut: {Authorization: "..."}}
headers:{ aut }

// ✅ {Authorization: "..."}
headers:{ ...aut }
```

### Código corregido completo

```js
async function hacerEj3() {
  console.log('\n--- Tarea 3: Fetch autenticado ---');

  if (!localStorage.getItem('tokenAutenticacion')) {
    localStorage.setItem('tokenAutenticacion', 'token-ficticio-abc123');
  }

  function getAuthHeaders(key) {
    const token = localStorage.getItem(key);
    return { Authorization: token };
  }

  try {
    const authHeaders = getAuthHeaders('tokenAutenticacion');
    const respuesta = await fetch(`${API}/posts/1`, {
      headers: { ...authHeaders }
    });
    if (!respuesta.ok) throw new Error(`HTTP ${respuesta.status}`);
    const datos = await respuesta.json();
    console.log('Post autenticado:', datos.title);
  } catch (error) {
    console.error('Error:', error.message);
  }
}
```

### Lección clave

> **Parámetros de Fetch son Objetos Literales.** El shorthand `aut` crea `{aut: {Authorization: "..."}}` — un objeto anidado que `fetch` no interpreta correctamente. Siempre usa spread (`...`) para merges de objetos:
> ```js
> headers: { aut }      // ❌ anida
> headers: { ...aut }   // ✅ desanida
> ```

### Bugs corregidos ✅

### 💀 BUG CRÍTICO: Sintaxis Rota (líneas 138-142)

```js
// Lo que escribiste:
headers:
  {'Content-Type':'application/json;charset=UTF-8'},
  {...aut}            // ← spread fuera de headers
                      // ← falta coma
{body: postString}    // ← SyntaxError: dos objetos seguidos
```

**JavaScript no puede parsear esto.** El archivo ni siquiera carga.

### Cómo lo ve el parser:

```
Línea 138-139: headers: {...}    → Propiedad 2 ✓
Línea 140:     {...aut}          → Spread como propiedad 3
                                  ← falta coma
Línea 142:     {body: postString} → 💥 SyntaxError
```

### Fix: un solo objeto con todo adentro

```js
const resp = await fetch(`${API}${post}`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json; charset=UTF-8',
    ...aut                    // ← auth DENTRO de headers
  },
  body: JSON.stringify(miPost) // ← body como propiedad del options
});
```

### Código corregido completo


### Lección clave

> **Objetos literales y spread — reglas inflexibles:**
> - Cada propiedad separada por **coma**
> - Spread va **dentro del objeto** que quieres modificar
> - `body` es propiedad del **options**, no de headers
> - `{}` adyacente sin operador = **SyntaxError**
