## Ejercicio 1: Tu primera petición XHR - Corrección y práctica

¡Vamos a solucionar ese código! Tienes un par de detalles en la sintaxis y falta la URL para que el ejercicio funcione de verdad.

Para que puedas probarlo con datos reales, usaremos una URL de prueba pública (`[https://jsonplaceholder.typicode.com/posts/1](https://jsonplaceholder.typicode.com/posts/1)`) que devuelve un texto en formato JSON.

Aquí tienes la corrección paso a paso dentro de tu mismo esquema:

```javascript
// ─── TASK 1: Crear un XMLHttpRequest ────────────────────────
// 💡 Pista: El patrón básico es:
//   1. Crear:     const xhr = new XMLHttpRequest();

// ❌ Corrección: Tenías "const xhr =" duplicado y faltaba la palabra clave "new"
const xhr = new XMLHttpRequest();

//   2. Abrir:     xhr.open('METHOD', 'URL');
// 💡 Añadimos una URL real de prueba para poder hacer la petición
xhr.open('GET', 'https://jsonplaceholder.typicode.com/posts/1');

//   3. Configurar qué hacer cuando llegue la respuesta (onload)
// 💡 Definimos la función que se ejecutará cuando el servidor responda con éxito
xhr.onload = function() {
    if (xhr.status === 200) {
        // Mostramos en consola la respuesta del servidor (viene como texto)
        console.log("¡Éxito! Datos recibidos:", xhr.responseText);
    } else {
        console.error("Error en la petición. Estado:", xhr.status);
    }
};

//   4. Enviar:    xhr.send();
// 💡 Finalmente enviamos la petición al servidor
xhr.send();

```

### ¿Qué corregimos exactamente?

1. **`const xhr = new XMLHttpRequest();`**: En tu código tenías `const xhr = const xhr = XMLHttpRequest();`. Eliminamos la duplicidad y añadimos la palabra `new`, que es obligatoria para crear una nueva instancia del objeto.
2. **La URL**: Reemplazamos el signo de interrogación `?` por `'[https://jsonplaceholder.typicode.com/posts/1](https://jsonplaceholder.typicode.com/posts/1)'`.
3. **El bloque `onload**`: Añadimos la función que escucha el evento para que realmente puedas ver en la consola lo que el servidor devuelve cuando ejecutas el archivo.

### Entendiendo `send()`: No envías una respuesta, envías la petición

Esa parte suele confundir un poco al principio porque el flujo no ocurre en el orden en que lo escribimos. Vamos a aclararlo de forma muy sencilla.

Con `xhr.send()` **no estás enviando una respuesta**, sino que estás **enviando la petición (la pregunta)** al servidor.

Imagina que estás en un restaurante:

1. **`new XMLHttpRequest()`**: Consigues una hoja de papel para apuntar tu pedido.
2. **`xhr.open('GET', 'URL')`**: Escribes en la nota qué quieres (un café) y a dónde hay que pedirlo (a la cocina).
3. **`xhr.onload = function() { ... }`**: Aquí le dejas instrucciones escritas a tu cerebro: *"Cuando el camarero vuelva con el café, déjalo en la mesa y tómatelo"*. Ojo: el camarero aún no ha ido a la cocina, solo estás planificando qué harás cuando regrese.
4. **`xhr.send()`**: Este es el momento en el que le entregas la nota al camarero y este corre hacia la cocina. Tu código sigue su camino, y cuando la cocina termina el café, el camarero vuelve y se activa automáticamente el paso 3 (`onload`).

### El orden real en el que ocurre todo:

1. Creas el objeto.
2. Lo configuras.
3. Defines la estrategia (`onload`).
4. **Disparas la acción (`send()`)**.
5. *(El código sigue ejecutándose hacia abajo sin esperar)*.
6. **Mucho después:** El servidor responde, el navegador lo detecta y ejecuta lo que guardaste dentro de `onload`.

### JSON: ¿Qué es y por qué todos lo usan?

Sí, vas por muy buen camino. El formato JSON **es texto puro**, pero su propósito principal no es quedarse guardado en la base de datos o que el navegador lo muestre tal cual, sino servir como un **puente de comunicación**.

Para entenderlo de forma muy sencilla:

#### 1. ¿Por qué es texto puro?

Las computadoras no pueden enviar objetos de JavaScript vivos (con sus métodos y estructuras internas) a través de un cable de red. La red solo entiende texto. Por eso, JSON convierte un objeto de tu código en una simple cadena de texto (`string`) para que pueda viajar de un lugar a otro sin romperse.

#### 2. ¿Para qué lo necesita el navegador?

El navegador lo necesita para **recibir la información que le pide al servidor** mediante herramientas como `fetch()` o `XMLHttpRequest`.

Cuando tu código JavaScript recibe ese texto JSON del servidor, hace esto:

1. Recibe el texto puro.
2. Lo transforma en un objeto de JavaScript real usando `JSON.parse()`.
3. Ahora que ya es un objeto, JavaScript puede leer sus datos y pintar los elementos en la pantalla (como poner el nombre de un usuario en un perfil).

#### 3. ¿Para qué lo necesita la base de datos?

Aquí hay un matiz importante:

* **La mayoría de las bases de datos tradicionales (como SQL/PostgreSQL)** no guardan la información como JSON. Prefieren desarmar ese JSON y guardar cada dato en filas y columnas bien ordenadas (como una tabla de Excel).
* **Las bases de datos NoSQL (como MongoDB)** sí que guardan la información directamente en formatos idénticos o muy parecidos a JSON.

#### En resumen:

JSON es como un **idioma universal y ligero en texto plano**. El servidor traduce los datos de la base de datos a JSON, lo envía por internet, y el navegador lo traduce de JSON a JavaScript para poder usarlo en la página web.

### El viaje completo de los datos: Los dos caminos

¡Lo has clavado! Has resumido a la perfección todo el flujo de ida y vuelta. Entender este camino es el 90% de cómo funciona el desarrollo web moderno.

Para dejarlo impecable en tu cabeza, este es el viaje completo con los dos caminos:

#### Camino 1: Cuando el cliente (navegador) PIDE datos al servidor

1. **La Base de Datos SQL:** Tiene los datos guardados en filas y columnas.
2. **El Servidor (Backend):** Hace la consulta SQL, extrae los datos de las columnas y los transforma en un texto plano JSON usando una función (en Node.js, por ejemplo, se usa `JSON.stringify()`).
3. **El Internet:** El texto JSON viaja ligero por la red.
4. **El Cliente (Navegador):** Recibe el texto plano JSON, lo convierte en un objeto real de JavaScript con `JSON.parse()` y lo usa para pintar la web.

#### Camino 2: Cuando el cliente ENVIAR datos para guardar (un registro, un formulario)

1. **El Cliente (Navegador):** Toma el objeto de JavaScript con los datos que escribiste y lo convierte en texto JSON.
2. **El Internet:** El JSON viaja hacia el servidor.
3. **El Servidor (Backend):** Recibe el JSON, extrae sus propiedades (clave-valor) y construye una sentencia SQL (como un `INSERT INTO...`).
4. **La Base de Datos SQL:** Recibe esos valores limpios y los guarda perfectamente en sus celdas de filas y columnas.

Como ves, el backend (el servidor) actúa como el **traductor/intermediario** indispensable: es el que sabe cómo pasar de "columnas SQL" a "texto JSON" y viceversa. El navegador nunca toca la base de datos SQL directamente por motivos de seguridad y arquitectura.

### Códigos de estado HTTP: ¿Qué significa `status === 200`?

Sí, exacto. El código `200` significa que todo salió bien. Los códigos de estado HTTP se agrupan por rangos:

* **2xx – Éxito:**
  - **200 OK** – La petición fue exitosa y el servidor devolvió los datos.
  - **201 Created** – Se creó un nuevo recurso (común al hacer `POST`).
  - **204 No Content** – Todo salió bien pero no hay contenido que devolver (común al hacer `DELETE`).
* **3xx – Redirección:** El recurso se movió a otra ubicación.
* **4xx – Error del cliente:**
  - **404 Not Found** – No se encontró el recurso que pediste.
  - **403 Forbidden** – No tienes permiso para acceder.
* **5xx – Error del servidor:**
  - **500 Internal Server Error** – El servidor tuvo un problema interno.

Por eso comprobamos `xhr.status === 200`: para confirmar que el servidor respondió correctamente antes de usar los datos.

### Desglose completo del código: Las tres partes

El código completo se compone de tres bloques independientes. Vamos a separarlos:

#### Parte 1: XHR independiente (la versión correcta)

```javascript
const xhr = new XMLHttpRequest();
xhr.open('GET','https://jsonplaceholder.typicode.com/posts/1');
xhr.onload = function() {console.log(xhr.responseText);};
xhr.send();
```

Esta es la versión **limpia y funcional** — los 4 pasos del patrón XHR:
1. **Crear** el objeto de petición
2. **Abrir** con método + URL
3. **Definir** qué hacer cuando llegue la respuesta
4. **Enviar** la petición

#### Parte 2: Bloque `hacerEj` (la plantilla con bugs)

```javascript
hacerEj('TASK 1: Crear y enviar un XHR', () => { ... });
```

Este es el **envoltorio de evaluación**. Dentro repite el mismo patrón XHR pero con errores:

| Qué está mal | Por qué es un problema |
|---|---|
| `xhr.send()` está **dentro** de `onload` | La petición nunca se dispara — `send()` no se llama inicialmente |
| Falta `xhr.send()` en el placeholder `/* Tu código aquí */` | El ejercicio espera que el estudiante lo agregue ahí |
| `onload` no valida `xhr.status` | `JSON.parse` podría fallar si hay un error |

#### Parte 3: Segunda petición independiente

```javascript
const peticion = new XMLHttpRequest();
peticion.open('GET','https://jsonplaceholder.typicode.com/posts/1');
peticion.onload = function(){console.log(peticion.responseText)};
```

Una **segunda petición independiente** con el mismo patrón pero usando otro nombre de variable (`peticion` en vez de `xhr`). Es más simple — sin check de status, sin `JSON.parse` — solo muestra el texto crudo de la respuesta.

#### Resumen

| Parte | ¿Es correcta? | Nota |
|---|---|---|
| Parte 1 (XHR standalone) | ✅ Sí | Versión limpia y funcional |

### Código comentado línea por línea

#### Ejemplo básico

```javascript
// ═══════════════════════════════════════════════════════════════
// EJEMPLO BÁSICO: Crear un objeto XMLHttpRequest
// ═══════════════════════════════════════════════════════════════

// Creamos una nueva instancia de XMLHttpRequest (XHR).
// XMLHttpRequest es una API del navegador que permite hacer
// peticiones HTTP desde JavaScript sin recargar la página.
// Es la base de lo que llamamos AJAX.
const xhr = new XMLHttpRequest();

// Abrimos (configuramos) la petición con el método .open().
// Primer parámetro: 'GET' → tipo de petición (queremos OBTENER datos).
// Segundo parámetro: la URL de donde obtendremos los datos.
// Nota: .open() NO envía la petición todavía, solo la prepara.
xhr.open('GET','https://jsonplaceholder.typicode.com/posts/1');

// Definimos qué sucederá cuando la petición termine de cargar.
// .onload es un "event handler" (manejador de evento) que se ejecuta
// automáticamente cuando el servidor responde con éxito.
// Dentro usamos una función anónima (function() { ... })
// que recibe la respuesta del servidor.
xhr.onload = function() {
    // xhr.responseText contiene la respuesta del servidor como texto plano (string).
    // Lo imprimimos en la consola para ver qué llegó desde el servidor.
    console.log(xhr.responseText);
};

// .send() es lo que realmente ENVÍA la petición al servidor.
// Sin esta línea, la petición nunca se manda, no importa cuántas
// veces hayas llamado a .open() o configurado .onload.
// Nota: para peticiones GET, .send() no necesita argumentos.
// (Está comentado con // para no ejecutarlo en este ejemplo suelto)
//xhr.send();
```

#### Ejercicio dentro del wrapper `hacerEj()`

```javascript
// ═══════════════════════════════════════════════════════════════
// EJERCICIO DENTRO DEL WRAPPER hacerEj()
// ═══════════════════════════════════════════════════════════════

// La función hacerEj() es un "wrapper" (envoltorio) que ejecuta
// cada tarea de forma segura con try/catch.
// Beneficios:
//   1. Aísla cada ejercicio: si uno falla, los demás siguen funcionando.
//   2. Captura errores automáticamente y los muestra en la consola.
//   3. Imprime el nombre de cada tarea antes de ejecutarla.
//   4. El código del estudiante va DENTRO del bloque, no suelto.
hacerEj('TASK 1: Crear y enviar un XHR', () => {

    // Creamos un nuevo objeto XMLHttpRequest.
    // Cada petición necesita su propio objeto XHR.
    // No puedes reutilizar un XHR para múltiples peticiones simultáneas.
    const xhr = new XMLHttpRequest();

    // Configuramos la petición con .open():
    //   'GET' → Queremos OBTENER datos del servidor (no enviar).
    //   La URL → El endpoint (punto de acceso) de la API de prueba
    //            jsonplaceholder nos da datos falsos para practicar.
    xhr.open('GET', 'https://jsonplaceholder.typicode.com/posts/1');

    // Configuramos el evento onload: qué hacer cuando el servidor responda.
    // Esta función se ejecuta DESPUÉS de que .send() envíe la petición
    // y el servidor devuelva una respuesta completa.
    xhr.onload = function() {

        // Verificamos el código de estado HTTP de la respuesta.
        //   200 = "OK" → La petición fue exitosa.
        //   404 = "Not Found" → El recurso no existe.
        //   500 = "Internal Server Error" → Error del servidor.
        // Siempre es buena práctica verificar el status antes de procesar.
        if (xhr.status === 200) {

            // La respuesta viene como texto plano (string) en xhr.responseText.
            // JSON.parse() convierte ese string en un objeto JavaScript real
            // que podemos usar (acceder a propiedades, recorrer, etc.).
            // Ejemplo: '{"id":1,"title":"..."}' → { id: 1, title: "..." }
            const datos = JSON.parse(xhr.responseText);

            // Mostramos el objeto ya convertido en la consola.
            // Ahora podemos usar datos.id, datos.title, datos.body, etc.
            console.log('Respuesta recibida:', datos);

        } else {
            // Si el status NO es 200, algo salió mal.
            // console.error() imprime en ROJO en la consola (fácil de detectar).
            // xhr.status → el código numérico (ej: 404, 500).
            // xhr.statusText → la descripción textual (ej: "Not Found").
            console.error('Error HTTP:', xhr.status, xhr.statusText);
        }
    };

    // ¡AQUÍ se envía la petición real al servidor!
    // Sin .send(), todo lo anterior (.open, .onload) no tendría efecto.
    // Para peticiones GET, .send() se llama sin argumentos.
    // Si fuera POST, aquí irían los datos: xhr.send(datosParaEnviar);
    xhr.send();
});
```

#### Flujo visual del patrón XHR

```
 new XMLHttpRequest()    ← 1. Crear el objeto
        │
      .open()            ← 2. Configurar: ¿qué método? ¿a qué URL?
        │
     .onload = ...       ← 3. Definir: ¿qué hago con la respuesta?
        │
      .send()            ← 4. ¡Enviar la petición al servidor!
        │
   (servidor responde)   ← 5. Se ejecuta onload automáticamente
        │
 JSON.parse(response)   ← 6. Convertir texto → objeto JavaScript
```

### Código comentado detallado: Guía de estudio

Aquí tienes el código completamente comentado paso a paso para que te sirva como una guía de estudio clara y detallada, identificando con precisión qué hace cada línea:

```javascript
// Instanciamos el objeto constructor para gestionar la comunicación HTTP
const xhr = new XMLHttpRequest();

// 2. Abrir: Configuramos la petición indicando el verbo HTTP ('GET' para leer) y el endpoint o dirección del servidor

// 3. Configurar qué hacer cuando llegue la respuesta (onload)
// Asignamos una función anónima al evento onload. Esta función quedará "a la espera" en segundo plano.

    // Cuando el servidor responda, imprimimos en consola el texto JSON crudo recibido (texto plano)
    console.log(xhr.responseText);

// xhr.send(); -> Esta línea está comentada, por lo que esta petición suelta de arriba nunca se llegará a disparar.


// Ejecución estructurada dentro del entorno de pruebas hacerEj
hacerEj('TASK 1: Crear y enviar un XHR', () => {
    // Creamos un nuevo objeto de petición específico para esta tarea
    const xhr = new XMLHttpRequest();

    // Establecemos el método de obtención de datos (GET) y la URL destino
    xhr.open('GET', 'https://jsonplaceholder.typicode.com/posts/1');

    // Declaramos el manejador de eventos que se activará ÚNICAMENTE cuando la respuesta haya retornado con éxito de la red

            // Si el estado no es 200 (por ejemplo, 404 o 500), capturamos e imprimimos los detalles del fallo del servidor
            console.error('Error HTTP:', xhr.status, xhr.statusText);
        }
    };

    // ✅ FUERA del callback (onload): Ejecutamos la orden de salida. 
    // Aquí es donde el navegador toma la configuración previa y lanza la petición real a través de la red de internet.
    xhr.send(); 
});
```
