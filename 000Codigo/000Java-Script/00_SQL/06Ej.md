### The `prompt()` function (lines 94-122)

This is the infinite loop that keeps the app running:

```js
function prompt() {
  rl.question('> ', (line) => {          // 1. waits for user input
    const parts = line.trim().split(' '); // 2. splits input by spaces
    const command = parts[0].toLowerCase();// 3. first word = command
    const args = parts.slice(1).join(' '); // 4. rest = argument(s)

    switch (command) {                     // 5. routes to correct function
      case 'list':     listTasks();                          break;
      case 'add':      addTask(args);                        break;
      case 'complete': completeTask(parseInt(args, 10));     break;
      case 'delete':   deleteTask(parseInt(args, 10));       break;
      case 'exit':     db.close(); console.log('Goodbye!'); process.exit(0);
      default:         console.log('Unknown command...');
    }
    prompt();                              // 6. calls itself again (recursive)
  });
}
```

### How input parsing works

| You type | `command` | `args` | Function called |
|---|---|---|---|
| `list` | `"list"` | `""` | `listTasks()` |
| `add Buy milk` | `"add"` | `"Buy milk"` | `addTask("Buy milk")` |
| `complete 3` | `"complete"` | `"3"` | `completeTask(3)` |
| `delete 5` | `"delete"` | `"5"` | `deleteTask(5)` |
| `exit` | `"exit"` | `""` | closes db and exits |

### Key details

- **`parts.slice(1).join(' ')`** — takes everything after the first word and rejoins it with spaces, so `add learn SQL with friends` preserves the full task name
- **`parseInt(args, 10)`** — converts the string `"3"` to the number `3` for `complete` and `delete` commands
- **`rl.question('> ', callback)`** — prints `> ` and waits; the callback fires when the user presses Enter
- **Recursion** — `prompt()` calls itself at the end of the callback, creating an infinite loop that keeps asking for commands until `process.exit(0)` terminates the process

## Tasks 3 & 5: INSERT and DELETE bugs

**Task 3 (line 52) — `.all()` should be `.run()`:**

```js
const info = db.prepare('INSERT INTO todos (task) VALUES (?)').all(taskName);
//                                                           ^^^
```

`.all()` returns rows (for SELECT queries). For INSERT, use `.run()` which returns `{ changes, lastInsertRowid }`.

Fix: `.run(taskName)`

## Task 4: Complete a task

```js
function completeTask(id) {
  const info = db.prepare('UPDATE todos SET completed = 1 WHERE id = ?').run(id);
  if (info.changes === 0) {
    console.log(`Error: Task with ID ${id} not found.`);
  } else {
    console.log(`Task ${id} marked as completed!`);
  }
}
```

### The SQL

```sql
UPDATE todos SET completed = 1 WHERE id = ?
```

| Part | Meaning |
|---|---|
| `UPDATE todos` | Which table to modify |
| `SET completed = 1` | Change the `completed` column to `1` (true — "done") |
| `WHERE id = ?` | Only update the row with this specific `id`; the `?` is filled with the `id` parameter via `.run(id)` |

Without `WHERE id = ?`, every task would be set to completed — which you don't want.

### The method — `.run()`

```js
db.prepare('...').run(id)
```

- `.run()` is for INSERT, UPDATE, DELETE — queries that **modify** data
- Returns an object `{ changes, lastInsertRowid }`
- `info.changes` tells you how many rows were affected

### The logic after

```js
if (info.changes === 0) {
  // No row matched that ID → task doesn't exist
  console.log(`Error: Task with ID ${id} not found.`);
} else {
  // info.changes will be 1 (one row updated)
  console.log(`Task ${id} marked as completed!`);
}
```

### Concrete example

Database state:

```
id: 1, task: "Buy milk",  completed: 0
id: 2, task: "Walk dog",  completed: 0
```

User types `complete 2`:
1. `id` = `2` (converted from string `"2"` by `parseInt` on line 107)
2. SQL runs: `UPDATE todos SET completed = 1 WHERE id = 2`
3. `info.changes` = `1` (matched row 2)
4. Prints: `Task 2 marked as completed!`

User types `complete 99`:
1. `id` = `99`
2. SQL runs: `UPDATE todos SET completed = 1 WHERE id = 99`
3. `info.changes` = `0` (no task with id 99)
4. Prints: `Error: Task with ID 99 not found.`

### Why `.run()` and not `.all()`?

- `.all()` returns an **array of rows** — for SELECT queries
- `.run()` returns `{ changes, lastInsertRowid }` — for INSERT/UPDATE/DELETE
- You need `info.changes` to check if the update actually found a row, so `.run()` is correct here
