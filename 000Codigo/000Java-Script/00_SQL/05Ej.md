# Debugging Report: 05Ej.js

## Issue
The SQL query in Task 1 had multiple syntax errors:

```sql
-- BEFORE (broken)
SELECT order_id, user_name (u.name),quantity FROM orders INNER JOIN u.id WITH users;

-- AFTER (fixed)
SELECT orders.id AS order_id, users.name AS user_name, quantity FROM orders INNER JOIN users ON orders.user_id = users.id
```

## Errors Found

| Error | Problem | Fix |
|---|---|---|
| `order_id` | Column is `id` in the orders table, not `order_id` | `orders.id AS order_id` |
| `user_name (u.name)` | Invalid SQL syntax; alias `u` was never defined | `users.name AS user_name` |
| `INNER JOIN u.id WITH users` | Completely wrong JOIN syntax | `INNER JOIN users ON orders.user_id = users.id` |

## INNER JOIN Pattern

```
INNER JOIN second_table ON first_table.foreign_key = second_table.primary_key
```

Applied to Task 1:

```sql
INNER JOIN users ON orders.user_id = users.id
```

- `users` = the second table to join
- `orders.user_id` = foreign key in the first table (orders)
- `users.id` = primary key in the second table (users)

## INNER JOIN Table Order

For `INNER JOIN`, the order of tables does **not** matter:

```sql
FROM orders INNER JOIN users ON orders.user_id = users.id
-- same result as
FROM users INNER JOIN orders ON users.id = orders.user_id
```

Both return identical rows. Table order **does** matter for `LEFT JOIN` / `RIGHT JOIN` (see Task 2).

## ON Condition Commutative

The condition in `ON` is **commutative** — swapping sides of `=` doesn't change anything:

```sql
ON orders.user_id = users.id   -- ✅
ON users.id = orders.user_id   -- ✅ equivalent
```

Both produce identical results. SQL just checks if the two values match; left/right position doesn't matter.

## Task 3: 3-Table Join (Detailed Orders)

Original broken query:

```sql
SELECT order.id AS id_Pedido, user.name AS nombre_Us, product.name AS nombre_Prod, 
       quantity, quantity * price AS precio_Total 
FROM users, products, orders 
INNER JOIN products ON products.product_id = orders.product_id orders 
INNER JOIN USERS on users.id = orders.user_id;
```

| Error | Problem | Fix |
|---|---|---|
| `order.id` | Wrong table name (should be `orders`) | `orders.id` |
| `user.name` | Wrong table name (should be `users`) | `users.name` |
| `product.name` | Wrong table name (should be `products`) | `products.name` |
| `products.product_id` | Wrong column (PK is `id`, not `product_id`) | `products.id` |
| `FROM users, products, orders INNER JOIN` | Mixing comma-joins with explicit JOIN creates cartesian product | Use only explicit JOINs |
| dangling `orders` between JOINs | Extra word breaking syntax | Remove, add proper ON clause |
| unqualified `price` | Ambiguous across tables | `products.price` |
| `USERS` | Inconsistent casing | `users` |

Correct version:

```sql
SELECT orders.id AS id_Pedido, 
       users.name AS nombre_Us, 
       products.name AS nombre_Prod, 
       orders.quantity, 
       orders.quantity * products.price AS precio_Total 
FROM orders 
INNER JOIN users ON orders.user_id = users.id 
INNER JOIN products ON orders.product_id = products.id
```

### 3-Table Join Pattern

When joining 3 tables with two foreign keys, chain the JOINs:

```
FROM main_table 
INNER JOIN table1 ON main_table.fk1 = table1.pk 
INNER JOIN table2 ON main_table.fk2 = table2.pk
```

Each `INNER JOIN` adds a new table by matching a foreign key from an already-included table.
