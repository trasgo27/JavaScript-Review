# Sumario: localStorage & Cookies (Nivel Beginner)

---

## localStorage

### ¿Qué es?
Almacenamiento clave-valor persistente en el navegador. Los datos **no expiran** y **no se envían al servidor**. Límite ~5-10MB por dominio.

### Métodos principales

| Método | Descripción |
|---|---|
| `setItem(key, value)` | Guarda un valor (siempre string) |
| `getItem(key)` | Obtiene un valor o `null` si no existe |
| `removeItem(key)` | Elimina una clave |
| `clear()` | Elimina todos los datos del dominio |
| `key(index)` | Obtiene el nombre de la clave en la posición `index` |

### Propiedades

| Propiedad | Descripción |
|---|---|
| `length` | Número de elementos almacenados |

### Ejemplo básico

```js
localStorage.setItem('nombre', 'Juan');
const nombre = localStorage.getItem('nombre'); // 'Juan'
localStorage.removeItem('nombre');
localStorage.clear();
```

### Errores frecuentes

1. **Guardar objetos sin stringify**
   ```js
   localStorage.setItem('user', {name: 'Juan'}); // Guarda "[object Object]"
   // ✅ Correcto:
   localStorage.setItem('user', JSON.stringify({name: 'Juan'}));
   JSON.parse(localStorage.getItem('user'));
   ```

2. **Olvidar parsear al leer**
   ```js
   const edad = localStorage.getItem('edad'); // string "25"
   // ❌ edad + 1 = "251"
   // ✅ Number(localStorage.getItem('edad'))
   ```

3. **Asumir que siempre existe**
   ```js
   const val = localStorage.getItem('no-existe'); // null
   // ❌ val.prop -> TypeError
   // ✅ if (val !== null) { ... }
   ```

4. **No manejar `QuotaExceededError`** (espacio lleno, modo incógnito en algunos navegadores)
   ```js
   try { localStorage.setItem('x', 'y'); }
   catch (e) { console.warn('Storage lleno'); }
   ```

5. **Usar claves duplicadas sin querer** — se sobrescribe silenciosamente.

## Cookies

### ¿Qué es?
Pequeños datos (máx. 4KB) que el navegador almacena y **envía automáticamente al servidor** en cada petición HTTP. Tienen fecha de expiración.

### Propiedades principales (atributos)

| Atributo | Descripción |
|---|---|
| `expires` / `max-age` | Fecha de expiración |
| `path` | Ruta donde aplica (por defecto `/`) |
| `domain` | Dominio (por defecto el actual) |
| `secure` | Solo se envía por HTTPS |
| `SameSite` | `Strict`, `Lax` (default) o `None`; controla envío cross-site |
| `HttpOnly` | No accesible desde JS (solo servidor) |

### Métodos (API básica)

```js
// Leer todas
console.log(document.cookie); // "clave1=val1; clave2=val2"

// Escribir/actualizar
document.cookie = "nombre=Juan; max-age=3600; path=/";

// Eliminar (poner fecha pasada)
document.cookie = "nombre=; max-age=0; path=/";
```

### Errores frecuentes

1. **Pensar que `document.cookie` es un objeto**
   ```js
   // ❌ document.cookie.nombre = 'Juan';
   ```
   Es un string. Para leer una cookie hay que parsearlo:
   ```js
   const cookies = Object.fromEntries(
     document.cookie.split('; ').map(c => c.split('='))
   );
   ```

2. **No especificar `path`**
   ```js
   document.cookie = "x=1";   // path = ruta actual
   // Al leer desde otra ruta no existe
   // ✅ document.cookie = "x=1; path=/";
   ```

3. **Olvidar `encodeURIComponent`** en valores con caracteres especiales (espacios, `;`, `=`)
   ```js
   // ❌ document.cookie = "nombre=Juan Pérez";
   // ✅ document.cookie = `nombre=${encodeURIComponent("Juan Pérez")}`;
   ```

4. **Ignorar `SameSite`** — navegadores modernos lo setean como `Lax` por defecto; puede bloquear cookies en peticiones cross-origin.

5. **Almacenar datos sensibles** — las cookies viajan en cada request. No guardes passwords o tokens sin `secure` + `HttpOnly`.

6. **No respetar el límite de 4KB** — intentar guardar más de ~4096 bytes puede truncar o fallar silenciosamente.

---

## Comparativa rápida

| Característica | localStorage | Cookies |
|---|---|---|
| Capacidad | 5-10 MB | 4 KB |
| Expiración | Manual (nunca expira) | Configurable |
| Enviada al servidor | No | Sí (cada request HTTP) |
| Accesible desde JS | Sí | Sí (si no tiene HttpOnly) |
| Persistencia | Hasta borrarse | Hasta expirar |
| Sincrónica | Sí | Sí |

---

## Regla de oro
- **localStorage** → datos solo del cliente (preferencias, carrito temporal, caché)
- **Cookies** → datos que necesita el servidor (sesión, autenticación, tracking)
